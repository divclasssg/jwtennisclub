# 회원 휴회 시작 월 설계

## 배경

현재 회원 휴회는 `members.status = 'paused'`라는 현재 상태만 저장한다. 회비 화면도 선택한 조회 월과 무관하게 현재 `active` 회원만 조회하므로, 2026년 8월부터 휴회할 회원을 미리 휴회 처리하면 2026년 7월 회비 화면에서도 해당 회원이 사라진다.

## 목표

- 휴회 회원에게 휴회 시작 월을 저장한다.
- 휴회 시작 월 이전의 회비 및 정모 기록은 활동 회원과 동일하게 유지한다.
- 휴회 시작 월부터 회비 및 새 정모 월 명단 대상에서 제외한다.
- 기존 휴회 회원인 엄다해 회원의 휴회 시작 월을 2026년 8월로 보정한다.

## 범위

이번 변경은 현재 진행 중인 한 번의 휴회에 대한 시작 월을 지원한다. 여러 번의 휴회·복귀 이력과 휴회 종료 월은 다루지 않는다. 추후 복귀 이력까지 과거 시점 기준으로 보존해야 한다면 별도 휴회 기간 이력 테이블로 확장한다.

## 데이터 모델

`members` 테이블에 `pause_start_month date` 컬럼을 추가한다.

- 값은 월의 첫날이어야 한다.
- `status = 'paused'`이면 값이 필수다.
- `status <> 'paused'`이면 값은 `null`이어야 한다.
- 기존 `paused` 회원은 마이그레이션에서 `2026-08-01`로 보정한다.
- 월 단위 비교에 사용하므로 시간대의 영향을 받지 않는 `date`를 사용한다.

## 회원 등록·수정

회원 폼에 `휴회 시작 월` 입력을 추가한다.

- 상태가 `휴회`일 때 필수다.
- 상태가 `활동중` 또는 `탈퇴`일 때는 비워야 한다.
- 브라우저에서는 `month` 입력을 사용하고 서버에서 `YYYY-MM` 형식을 검증한다.
- DB RPC에는 해당 값을 월 첫날인 `YYYY-MM-01`로 전달한다.
- 저장 RPC와 DB 제약이 동일한 상태/시작 월 불변식을 검증한다.

회원 목록의 `활동`, `휴회`, `탈퇴` 탭은 현재 상태 분류를 그대로 유지한다. 휴회 탭에서는 필요하면 휴회 시작 월을 확인할 수 있도록 목록 데이터에 값을 포함한다.

## 회비 대상 판정

선택한 회비 조회 월을 `period_month`라고 할 때 대상 조건은 다음과 같다.

```text
status = active
OR
(status = paused AND period_month < pause_start_month)
```

따라서 엄다해 회원의 `pause_start_month = 2026-08-01`인 경우:

- 2026년 7월 회비 화면: 표시
- 2026년 8월 이후 회비 화면: 제외

회비 등록, 회원별 월간 메모 저장, CSV 회비 가져오기에서도 같은 월 기준 판정을 사용한다. 단순한 현재 `status = active` 검사로 되돌아가지 않도록 판정 로직을 공통화하거나 각 경계에 같은 조건을 명시적으로 적용한다.

이미 저장된 `fee_payments` 기록은 변경하거나 삭제하지 않는다. 월별 정산은 기존처럼 저장된 납부 기록을 기준으로 계산한다.

## 정모 명단 판정

정모 월 명단을 준비하거나 동기화할 때도 명단의 `period_month`를 기준으로 다음 조건을 사용한다.

```text
status = active
OR
(status = paused AND roster.period_month < pause_start_month)
```

- 이미 잠긴 과거·현재 월 명단과 참석 기록은 변경하지 않는다.
- 준비 중인 2026년 8월 명단에서는 엄다해 회원을 제외한다.
- 휴회 시작 월 이전 명단을 재구성할 경우에는 포함한다.
- 회차별 임시 참석 추가도 해당 회차의 월 기준으로 동일하게 판정한다.

## 마이그레이션

새 마이그레이션은 다음 순서로 실행한다.

1. `pause_start_month` nullable 컬럼을 추가한다.
2. 기존 `paused` 회원의 값을 `2026-08-01`로 보정한다.
3. 월 첫날 제약과 상태 일치 제약을 추가한다.
4. 회원 저장 및 조회 RPC가 새 컬럼을 처리하도록 갱신한다.
5. 정모 명단 관련 SQL이 월 기준 휴회 판정을 사용하도록 갱신한다.

마이그레이션은 이름을 조건으로 특정 회원을 찾지 않는다. 현재 존재하는 모든 `paused` 회원을 2026년 8월 시작으로 보정하며, 운영 데이터상 대상은 엄다해 회원 한 명이라는 확인을 전제로 한다.

## 오류 처리

- 휴회인데 시작 월이 없으면 회원 폼에서 저장을 거부한다.
- 활동중 또는 탈퇴인데 시작 월이 있으면 저장을 거부한다.
- `YYYY-MM`이 아니거나 유효하지 않은 월이면 저장을 거부한다.
- DB 직접 호출에서도 같은 불변식을 제약 조건으로 차단한다.
