# 모바일 공통 UI 및 리스트 전환 설계

## 목표

피그마의 모바일 프레임 `12:189`를 기준으로 모든 인증 화면에 일관된 모바일 셸을 적용한다. 모바일에서는 운영에 필요한 핵심 정보와 작업만 남기고, 표를 전용 리스트로 바꿔 375px 및 402px 화면에서 가로 스크롤이나 레이아웃 깨짐이 생기지 않게 한다.

우선순위는 다음과 같다.

1. 문서와 주요 콘텐츠에 가로 스크롤이 생기지 않는다.
2. 화면별 핵심 정보와 필수 작업을 첫 화면에서 확인할 수 있다.
3. 피그마의 모바일 셸, 간격, 메뉴, 제목, 검색 영역, 평면형 목록 표현을 따른다.
4. 데스크톱 셸과 표는 기존 동작을 유지한다.

## 적용 범위

이번 범위에 포함한다.

- 모든 인증 화면의 공통 모바일 상단 브랜드 바
- 햄버거 버튼으로 여는 계정 메뉴
- 모바일 가로 스크롤 주요 메뉴
- 공통 모바일 제목 바
- 모바일 필터와 작업 바의 한 열 반응형 배치
- 회원, 회비, 지출, 정산, 정모 표면의 모바일 리스트
- 긴 텍스트, 작업 버튼, 폼 컨트롤의 넘침 방지
- 375px, 402px, 데스크톱 회귀 검증

이번 범위에서 제외한다.

- 데스크톱 정보 구조나 표 컬럼 변경
- 데이터 모델, RPC, 권한, 정렬 규칙 변경
- 일정 월간·주간 캘린더의 재설계
- 로그인 화면 변경
- 모바일에서 부가 정보를 펼치는 상세 disclosure
- 피그마 파일 자체 수정

## 확정된 제품 원칙

- 모바일 접근성 확장은 이번 작업의 우선순위가 아니다. 기존 HTML 의미와 접근 가능한 이름을 의도적으로 훼손하지는 않지만, 부가 정보를 보존하기 위한 별도 펼침 UI는 만들지 않는다.
- 모바일에서는 핵심 정보만 표시하고 연락처, 그룹, 가입일, 긴 메모처럼 현재 작업에 필수적이지 않은 정보는 목록에서 생략할 수 있다.
- 모바일에서 데스크톱 표를 축소하거나 가로 스크롤시키지 않는다. 같은 정렬 결과를 사용하는 별도의 세로 리스트를 제공한다.
- 리스트 항목은 피그마처럼 카드 그림자나 둥근 외곽선보다 구분선 중심의 평면형 행으로 표시한다.
- 작업 버튼은 콘텐츠 너비를 침범하지 않게 축소하거나 다음 줄로 감싼다.
- 모바일 레이아웃 정확성은 고정 높이를 억지로 맞추는 것보다 화면 깨짐과 가로 넘침 방지를 우선한다.

## 공통 모바일 셸

### 상단 브랜드 바

`AppShell`이 모바일에서 64px 높이의 흰색 브랜드 바를 표시한다.

- 왼쪽에 48px 터치 영역의 햄버거 버튼
- 오른쪽에 `JW TENNIS CLUB` 브랜드
- 피그마의 17px 굵은 제목 토큰 사용
- 데스크톱의 검은 전역 브랜드 바는 모바일에서 이 구조로 대체

피그마 노드에서 제공하는 메뉴 아이콘 자산이나 코드 연결 컴포넌트를 우선 사용한다. 정확한 자산을 얻을 수 없을 때만 프로젝트에 이미 존재하는 동일한 메뉴 아이콘을 재사용하며 임의 SVG를 새로 그리지 않는다.

### 계정 메뉴

햄버거 버튼은 모바일 계정 메뉴를 연다.

- 사용자 이름
- 역할과 직책
- 비밀번호 변경
- 로그아웃

계정 메뉴는 브랜드 바 아래에 겹쳐 표시하여 본문 높이를 밀어내지 않는다. 긴 사용자 이름과 역할은 줄바꿈할 수 있고 메뉴 자체는 viewport 너비를 넘지 않는다. 데스크톱 사용자 바는 그대로 유지한다.

### 주요 메뉴

브랜드 바 아래에 56px 높이의 가로 메뉴 바를 둔다.

- 홈, 회원, 회비, 지출, 일정, 권한에 따른 정모, 정산 순서 유지
- 현재 메뉴는 검은 배경과 흰 글자의 알약 형태
- 나머지는 회색 배경과 보조 텍스트 색상의 알약 형태
- 각 메뉴는 줄바꿈하지 않고 메뉴 바 내부에서만 가로 스크롤
- 페이지 본문이나 문서에는 가로 스크롤을 전파하지 않음

### 제목과 콘텐츠

기존 `PageTitleContext`를 유지하고 주요 메뉴 아래에 56px 공통 제목 바를 표시한다. 모바일에서는 기존 사용자 바를 숨기므로 셸의 세로 행은 브랜드 바, 주요 메뉴, 제목 바, 콘텐츠 순서가 된다. 콘텐츠는 남은 높이 안에서 세로 스크롤한다.

## 공통 모바일 도구 영역

`Tabs`, `FilterBar`, `PanelHeader`, `SummaryGrid`의 모바일 규칙을 피그마 구조에 맞춘다.

- 탭은 56px 높이와 하단 활성 표시를 유지
- 필터는 한 열로 배치
- 입력, 선택, 월 입력, 조회 버튼은 사용 가능한 너비를 채움
- 회원 검색은 피그마처럼 입력과 조회 버튼을 세로로 쌓음
- 패널 헤더는 총계와 등록 작업을 한 행에 유지하되, 너비가 부족하면 작업만 다음 줄로 이동
- 요약은 기존 한 열 모바일 규칙을 유지
- 모든 자식에 `min-width: 0`을 적용할 수 있는 구조를 사용

필터와 패널 헤더의 모바일 변경은 모든 관리 화면에 공통 적용한다. 페이지별 고유 데스크톱 배치는 변경하지 않는다.

## 표의 모바일 리스트 전환

데스크톱 `DataTable`은 유지한다. 전화기 breakpoint 이하에서는 표 컨테이너를 숨기고 같은 서버 데이터와 정렬 결과를 받는 전용 리스트를 표시한다.

### 회원

회원 행에는 다음만 표시한다.

- 이름
- 회원번호
- 직책
- 운영진/일반회원 구분
- 활동/휴회/탈퇴 상태
- 권한이 있을 때 수정 링크

연락처, 그룹, 가입일은 모바일 목록에서 표시하지 않는다. 이름은 17px 굵은 텍스트, 나머지 메타 정보는 13px 보조 텍스트로 한 줄 우선 배치하고 공간이 부족하면 자연스럽게 줄바꿈한다.

### 회비

기존 모바일 리스트를 더 압축된 평면형 행으로 정리한다.

- 회원 이름과 회원번호
- 납부 상태
- 기준 또는 실제 금액
- 납부 완료 시 납부일
- 납부 처리 또는 취소
- 메모가 있으면 짧은 요약과 메모 작업

운영진 구분처럼 납부 처리에 직접 필요하지 않은 부가 정보는 모바일에서 생략할 수 있다. 긴 메모는 한 줄 말줄임으로 제한한다.

### 지출

새 `ExpenseMobileList`를 추가한다.

- 지출 내용
- 사용일
- 카테고리
- 금액
- 증빙 보기 또는 증빙 상태
- 수정과 삭제 작업

긴 메모는 모바일 목록에서 생략한다. 지출 내용은 줄바꿈하고 금액과 작업 영역은 줄어들지 않게 한다. 수정과 삭제는 별도 작업 줄에서 감쌀 수 있다.

### 정산

새 `SettlementCategoryMobileList`를 추가한다.

- 카테고리
- 건수
- 금액

각 항목은 카테고리를 제목으로, 건수와 금액을 보조 행으로 표시한다. 데스크톱 정렬 결과를 그대로 사용한다.

### 정모

기존 `MeetingMobileList`를 유지한다. 다음 공통 넘침 규칙만 강화한다.

- 제목과 장소는 줄바꿈
- 상태와 회차 메타는 여러 줄로 감쌀 수 있음
- 명단 및 관리 작업은 사용 가능한 너비 안에서 감쌈
- 내부에 고정 최소 너비를 두지 않음

## 컴포넌트 경계

- `AppShell`: 데스크톱/모바일 셸 구조와 계정 메뉴 데이터 소유
- `ShellNavigation`: 현재 경로 판정과 공통 주요 메뉴 렌더링
- `ManagementPageTemplate`: 제목 발행과 화면별 탭, 요약, 필터, 목록 순서 유지
- 공통 atoms/molecules: 모바일 입력 너비, 필터, 탭, 패널 헤더의 반응형 표현
- 화면별 모바일 리스트: 해당 도메인의 핵심 정보 선택과 작업 렌더링

데이터 조회, 정렬, 필터 URL, 서버 작업은 기존 페이지가 계속 소유한다. 모바일 리스트는 이미 계산된 행을 props로 받아 표시만 하며 별도 조회나 클라이언트 상태를 추가하지 않는다.

## 반응형 및 넘침 규칙

- 기존 전화기 breakpoint인 640px 이하에서 모바일 구조로 전환
- 모든 셸 및 목록 컨테이너의 최대 너비는 viewport를 넘지 않음
- flex/grid 콘텐츠 자식에 필요한 `min-width: 0` 적용
- 사용자 제공 텍스트는 `overflow-wrap: anywhere` 또는 제한된 말줄임 적용
- 고정 너비 대신 `width: 100%`, `max-width: 100%`, 유연한 grid/flex 사용
- 버튼 그룹은 `flex-wrap: wrap`
- 주요 메뉴의 가로 스크롤만 명시적으로 허용
- 문서, 셸 작업 공간, 페이지 콘텐츠, 데이터 패널에는 가로 스크롤 금지

## 오류 및 빈 상태

- 데이터 로드와 서버 작업 오류 처리는 기존 계약을 유지한다.
- 빈 목록은 기존 `EmptyState`를 그대로 사용한다.
- 권한이 없는 작업은 데스크톱과 동일하게 모바일에서도 표시하지 않는다.
- 긴 텍스트나 작업 수 증가가 레이아웃을 깨뜨리지 않도록 실제 최대 길이에 가까운 테스트 데이터를 사용한다.

## 테스트 전략

구현은 테스트 주도로 진행한다.

### 컴포넌트 테스트

- `AppShell` 모바일 브랜드, 메뉴 버튼, 계정 작업, 주요 메뉴 구조
- 회원 모바일 목록이 확정된 핵심 정보만 표시하고 연락처·그룹·가입일을 생략
- 회비 모바일 목록의 핵심 정보와 작업 유지
- 지출 모바일 목록의 내용, 날짜, 카테고리, 금액, 증빙, 관리 작업
- 정산 모바일 목록의 카테고리, 건수, 금액
- 권한에 따른 메뉴와 작업 노출 유지

### 회귀 검증

- 관련 집중 테스트
- 전체 `npm run test`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `git diff --check`

### 브라우저 검증

인증된 화면을 375×812, 402px 너비, 데스크톱 1440×900에서 확인한다.

- `document.documentElement.scrollWidth === window.innerWidth`
- 각 페이지의 주요 목록 컨테이너가 viewport 너비를 넘지 않음
- 주요 메뉴 이외의 가로 스크롤 영역이 없음
- 햄버거 계정 메뉴가 화면 밖으로 나가지 않음
- 회원, 회비, 지출, 정산, 정모에서 데스크톱 표가 숨고 모바일 리스트가 표시됨
- 등록, 수정, 삭제, 납부, 메모, 증빙 등 필수 작업이 화면 밖으로 잘리지 않음
- 데스크톱 셸과 표가 기존 형태로 유지됨
- 브라우저 콘솔 오류와 실패한 앱 요청이 없음

## 완료 기준

- 모든 인증 화면이 피그마 기반 공통 모바일 셸을 사용한다.
- 모바일의 모든 `DataTable` 표면이 전용 리스트로 대체된다.
- 회원 모바일 목록은 핵심 정보만 표시한다.
- 375px와 402px에서 주요 메뉴 이외의 가로 스크롤이 없다.
- 데스크톱 기능과 표가 회귀하지 않는다.
- 테스트, lint, TypeScript, 빌드, 정적 diff 검사와 가능한 브라우저 검증 결과를 사실대로 기록한다.
