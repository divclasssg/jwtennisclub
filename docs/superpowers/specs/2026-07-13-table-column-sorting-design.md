# Table Column Sorting Design

## Goal

회원, 회비, 지출, 정산 카테고리 테이블의 정렬 가능한 헤더 텍스트를 하나의 정렬 링크로 제공한다. 현재 필터 조건을 보존하며, 데스크톱 테이블과 모바일 목록이 동일한 정렬 결과를 사용하도록 한다.

## Scope

정렬 가능한 컬럼은 다음과 같다.

- 회원: 회원번호, 이름, 전화번호, 구분, 직책, 그룹, 상태, 가입일
- 회비: 회원번호, 이름, 구분, 상태, 기준 금액, 납부일, 메모
- 지출: 사용일, 카테고리, 내용, 금액, 메모
- 정산 카테고리: 카테고리, 건수, 금액

`관리`, `처리`, `증빙`처럼 사용자 작업이나 링크만 포함하는 컬럼은 정렬하지 않는다. 일정 캘린더와 모바일 카드 자체는 테이블이 아니므로 새 헤더를 추가하지 않는다.

## Interaction

각 정렬 가능한 헤더는 라벨과 로컬 인라인 SVG 아이콘 전체를 하나의 링크로 렌더링한다. 아이콘은 `mobiledata_arrows`처럼 위·아래 화살표를 항상 함께 표시한다. 현재 정렬 열이 아니면 두 화살표를 모두 비활성 색상으로 표시하며, 클릭하면 해당 열을 오름차순으로 정렬한다. 현재 정렬 열은 적용된 방향의 화살표만 활성 색상으로 강조하고 반대 방향 화살표는 비활성 색상으로 유지하며, 클릭할 때마다 활성 방향을 전환한다. Google Fonts나 Material Symbols 외부 링크는 사용하지 않는다.

링크의 접근 가능한 이름은 클릭 후 적용될 동작을 설명한다. 예를 들어 현재 회원번호가 오름차순이면 `회원번호 내림차순 정렬` 링크가 되고, 화면에서는 SVG의 위 화살표가 활성 색상으로 표시된다. 현재 선택된 정렬 링크는 `aria-current`와 `aria-sort`로 노출하고 시각적으로도 활성 상태를 구분한다. 정렬하지 않는 헤더는 기존 일반 텍스트 헤더를 유지한다.

## URL And Data Flow

정렬 상태는 각 목록 URL의 `sort`와 `direction` 검색 파라미터로 관리한다. `direction`은 `asc` 또는 `desc`만 허용한다. 각 페이지는 허용된 `sort` 값을 화이트리스트로 검증하고, 누락되거나 잘못된 값은 기존 기본 정렬을 사용한다.

정렬 링크를 만들 때 현재 페이지의 검색 파라미터를 복사하고 `sort`, `direction`만 교체한다. 따라서 회원 상태 탭, 회원 검색어, 회비 월과 검색어, 지출 월과 카테고리 필터, 정산 월 선택은 유지된다.

페이지가 서버에서 데이터를 불러온 뒤 화면 모델을 정렬한다. 이 방식은 DB 컬럼뿐 아니라 운영진 구분, 납부 상태, 기준 금액, 정산 집계처럼 파생된 값도 동일한 계약으로 처리한다. 정렬된 배열을 데스크톱 테이블과 모바일 목록에 함께 전달한다.

## Comparison Rules

- 문자열은 한국어 로케일과 숫자 인식을 사용하는 비교로 정렬한다.
- 날짜는 ISO 날짜 값을 비교한다.
- 금액과 건수는 숫자로 비교한다.
- 상태, 구분, 직책, 그룹은 화면에 표시되는 문자열을 비교한다.
- 전화번호는 화면에 표시되는 마스킹 또는 전체 번호 문자열을 비교한다.
- 값이 없는 항목은 오름차순과 내림차순 모두 마지막에 둔다.
- 기본 비교값이 같으면 기존 배열 순서를 보존하는 안정 정렬을 사용한다.

## Components

공통 정렬 헤더 컴포넌트는 헤더 라벨, 정렬 키, 현재 정렬 상태, 현재 URL 파라미터를 받아 다음 정렬 방향을 계산하고 단일 링크를 렌더링한다. 공통 정렬 도우미는 방향 검증, URL 생성, null-last 안정 정렬을 담당한다. 페이지별 모듈은 허용 키와 컬럼별 실제 비교값만 정의한다.

기존 `DataTable`은 스크롤과 테이블 스타일 책임만 유지한다. 정렬 상태나 데이터 의미를 공통 테이블 컴포넌트 내부에 숨기지 않는다.

## Error Handling

지원하지 않는 `sort` 또는 `direction` 값은 오류를 내지 않고 해당 페이지의 기존 기본 순서를 사용한다. 정렬 링크는 다른 필터 값을 삭제하지 않는다. null 또는 빈 값은 비교 중 예외 없이 마지막으로 이동한다.

## Styling

정렬 링크는 헤더 텍스트와 화살표를 함께 클릭할 수 있는 충분한 영역을 제공하며 기존 SCSS 디자인 토큰만 사용한다. 새 스타일 클래스는 의미 있는 kebab-case 이름을 사용한다. 모바일에서 테이블은 숨겨질 수 있지만 정렬된 데이터 순서는 모바일 목록에도 동일하게 적용된다.

## Testing

- 공통 도우미: 파라미터 검증, 필터 보존 URL, 오름차순/내림차순, null-last, 안정 정렬
- 공통 헤더: 단일 헤더 링크, 항상 유지되는 SVG 위·아래 화살표, 방향별 활성·비활성 상태, 다음 방향 URL, 접근 가능한 이름과 `aria-sort`
- 회원: 정렬 링크와 회원번호/이름/가입일 등 대표 문자열·날짜 정렬
- 회비: 납부 상태, 기준 금액, 납부일과 모바일 목록 순서
- 지출: 사용일, 카테고리, 금액 정렬
- 정산: 카테고리, 건수, 금액 정렬
- 회귀 검증: 기존 검색, 월 선택, 상태 탭, 액션 링크와 버튼 유지
