# 월별 회비 메모 설계

## 목표

운영진이 납부 여부와 관계없이 선택한 월의 회원별 회비 메모를 기록하고 수정한다. 메모는 납부 처리·납부 취소와 독립적으로 유지하며, 데스크톱 표와 모바일 카드에서 같은 흐름을 제공한다.

## 제품 범위

이번 범위에 포함한다.

- 활동중 회비 대상 회원마다 월별 메모 작업 제공
- 미납 및 납부 완료 상태에서 메모 입력·수정
- 빈 값 저장을 통한 메모 삭제
- 납부 처리·취소 후에도 메모 유지
- 기존 회비 납부 메모의 월별 메모 이전
- CSV `memo` 또는 `메모` 열 호환 유지
- 기존 회비 권한에 따른 조회·관리 제한

이번 범위에서 제외한다.

- 여러 달에 같은 메모를 일괄 복사하는 기능
- 메모 변경 이력과 작성자 이름 표시
- 메모 검색 및 필터
- 일반 회원의 메모 조회·작성
- 납부 금액이나 납부일 수정

## 확정된 사용자 경험

회비 관리의 각 회원 행과 모바일 카드에 독립된 메모 작업을 표시한다.

- 메모가 없으면 메모 컬럼에 `메모 입력` 버튼을 표시한다.
- 메모가 있으면 내용을 한 줄로 말줄임 표시하고 옆에 `수정` 버튼을 표시한다.
- 버튼을 누르면 해당 회원과 선택 월이 명시된 작은 `ModalDialog`를 연다.
- 팝업에는 최대 500자의 textarea와 `취소`, `저장` 작업을 제공한다.
- 기존 메모가 있으면 textarea의 초기값으로 채운다.
- 공백만 입력하거나 내용을 모두 지운 뒤 저장하면 해당 월 메모를 삭제한다.
- 저장 후 선택 월, 검색어, 정렬 상태를 유지한 회비 관리 화면으로 돌아온다.
- 납부 상태는 메모 버튼 노출과 저장 가능 여부에 영향을 주지 않는다.
- 납부 처리와 납부 취소 폼에는 메모 입력을 추가하지 않는다.

메모 전문은 팝업에서 확인한다. 표와 카드에는 긴 메모 전체를 펼치지 않아 기존 체크판의 스캔 밀도와 모바일 폭을 유지한다.

## 데이터 모델

새 `fee_monthly_notes` 테이블을 추가한다.

- `id`: UUID 기본 키
- `member_id`: `members.id` 외래 키
- `period_month`: 해당 월의 첫날
- `memo`: 앞뒤 공백을 제거한 1~500자 문자열
- `created_by`, `updated_by`: 작업한 인증 프로필
- `created_at`, `updated_at`: 감사 시각

`member_id + period_month` 조합을 고유하게 만들어 한 회원이 한 달에 하나의 메모만 갖게 한다. 빈 메모는 행으로 보관하지 않고 삭제한다. 회원 삭제는 기존 회원 이력 보존 정책에 맞춰 제한한다.

기존 `fee_payments.memo`는 CSV 호환과 안전한 점진 이전을 위해 이번 변경에서 제거하지 않는다. 마이그레이션은 기존의 비어 있지 않은 납부 메모를 `fee_monthly_notes`로 멱등 복사한다. 월별 메모를 화면의 단일 원본으로 사용하며, 이후 팝업 편집은 `fee_monthly_notes`만 변경한다.

CSV 등록은 기존 `memo` 열을 계속 받는다. `fee_payments` 삽입 시 같은 트랜잭션에서 비어 있지 않은 메모를 `fee_monthly_notes`에 upsert하는 DB 트리거를 추가한다. 따라서 CSV의 결제 등록과 월별 메모 생성은 함께 성공하거나 함께 실패한다. 팝업에서 월별 메모를 나중에 수정해도 호환용 `fee_payments.memo`를 역동기화하지 않으며, 화면은 항상 새 테이블 값만 읽는다.

## 권한과 보안

RLS는 기존 회비 권한 계약을 재사용한다.

- `fees.payments.view`: 월별 메모 조회
- `fees.payments.create` 또는 `fees.payments.update`: 메모 생성·수정·삭제

메모를 비우는 작업은 납부 기록 삭제가 아니라 월별 메모 편집이므로 `fees.payments.delete`를 요구하지 않는다. 현재 납부 등록을 담당하는 운영진도 메모를 계속 수정할 수 있도록 생성 또는 수정 권한 중 하나를 메모 관리 권한으로 인정한다.

서버 Action과 RLS가 모두 권한을 검증한다. 사용자가 전달한 회원 ID는 활동중 회비 대상 회원인지 확인하고, 월은 `YYYY-MM`을 해당 월 첫날로 정규화한다. 메모는 서버에서 앞뒤 공백을 제거하고 500자를 초과하면 저장하지 않는다.

CSV 동기화 트리거는 호출자의 권한 경계를 넓히지 않는다. 기존에 회비 납부 기록을 생성할 수 있는 요청 안에서만 실행되고, 임의의 다른 회원·월 데이터는 만들지 않는다.

## 애플리케이션 구조와 데이터 흐름

회비 페이지는 선택 월의 `fee_payments`와 `fee_monthly_notes`를 함께 조회해 회원별 체크판 행을 만든다. 납부 상태와 메모는 `member_id + period_month`로 각각 독립 결합한다.

메모 팝업은 URL 검색 파라미터를 사용한다.

- `note=<member-id>`: 편집할 회원
- 기존 `month`, `q`, `sort`, `direction`: 현재 화면 상태 유지

유효하지 않거나 현재 목록의 회비 대상이 아닌 회원 ID는 메모를 노출하지 않고 안전한 오류 또는 목록 복귀 상태로 처리한다. 팝업을 닫으면 `note`만 제거하고 나머지 검색 파라미터는 유지한다.

메모 저장 Server Action은 다음 순서로 동작한다.

1. 인증 사용자와 회비 관리 권한을 확인한다.
2. 회원 ID, 선택 월, 메모 길이를 검증한다.
3. 비어 있지 않으면 `member_id + period_month` 기준으로 upsert한다.
4. 비어 있으면 기존 월별 메모 행을 삭제한다.
5. `/fees`를 재검증하고 원래 필터·정렬 상태로 리디렉션한다.

## 오류 처리와 접근성

- 저장 실패 시 팝업을 유지하고 일반 사용자용 오류 메시지를 표시한다.
- 권한 없음, 잘못된 회원, 잘못된 월, 500자 초과를 구분해 처리하되 DB 원문 오류는 노출하지 않는다.
- 팝업 제목에 회원 이름과 대상 월을 포함한다.
- textarea에는 화면 label과 오류 메시지 연결을 제공한다.
- 키보드 포커스 트랩, `Escape`, 배경 클릭, 닫기 후 원래 메모 버튼으로의 포커스 복귀는 기존 `ModalDialog` 계약을 따른다.
- 메모가 있는 행의 `수정` 버튼은 접근 가능한 이름에 회원 이름을 포함한다.

## 테스트와 검증

TDD로 다음 동작을 회귀 테스트한다.

- 미납 회원과 납부 완료 회원 모두 메모 버튼 표시
- 메모 없음의 `메모 입력`과 메모 있음의 요약·`수정` 표시
- 데스크톱 표와 모바일 카드의 동일한 동작
- 메모 생성, 수정, 공백 저장 삭제
- 500자 경계와 공백 정규화
- 월·검색·정렬 검색 파라미터 유지
- 권한 없는 저장 거부와 잘못된 회원 차단
- 납부 처리·취소 후 메모 유지
- 기존 납부 메모 마이그레이션과 재실행 멱등성
- CSV 메모의 월별 메모 동기화와 트랜잭션 실패 롤백

구현 후 회비 집중 테스트, 전체 테스트, lint, TypeScript 검사, 프로덕션 빌드와 `git diff --check`를 실행한다. 데스크톱과 375px 모바일 브라우저에서 팝업, 긴 메모 말줄임, 화면 상태 유지, 콘솔 오류와 가로 넘침을 확인한다.
