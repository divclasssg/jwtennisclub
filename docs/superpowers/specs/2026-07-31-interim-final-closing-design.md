# 월간 중간 결산 및 최종 마감 설계

## 목표

운영자가 월이 끝나기 전에도 결산 스냅샷과 PDF를 만들 수 있게 한다. 중간 결산은 월중 현황을 공유하기 위한 불변 기록이며 원본 입력을 잠그지 않는다. 최종 마감은 해당 월의 회비·지출을 확정하고, 수정이 필요하면 결산 재개를 거치게 한다.

사용자 화면의 기존 `정산` 용어는 메뉴, 화면, 작업, 안내, 오류와 PDF 전체에서 `결산`으로 통일한다. 데이터베이스 테이블, RPC와 코드 내부의 `settlement` 식별자는 배포 호환성을 위해 유지한다.

## 제품 원칙

- 중간 결산과 최종 마감은 현재 월과 과거 월에 실행할 수 있다.
- 미래 월은 중간 결산과 최종 마감을 모두 거부한다.
- 결산 스냅샷이 생성되면 같은 날 즉시 PDF를 다운로드할 수 있다.
- 중간 결산 후에도 해당 월의 회비와 지출을 계속 입력·수정할 수 있다.
- 최종 마감 후에는 해당 월의 회비와 지출 변경을 차단한다.
- 최종 마감된 월을 수정하려면 먼저 결산 재개를 실행해야 한다.
- 모든 중간 결산본과 최종 마감본은 불변 버전으로 보존한다.
- PDF는 선택한 스냅샷만 사용하며 다운로드 시 원본 데이터를 다시 계산하지 않는다.

## 결산 유형과 버전

기존 `monthly_closings` 스냅샷 구조에 결산 유형을 추가한다.

- `interim`: 중간 결산
- `final`: 최종 마감

버전은 대상 월과 결산 유형별로 독립적으로 증가한다.

예시:

1. 중간 결산 v1
2. 원본 회비·지출 수정
3. 중간 결산 v2
4. 최종 마감 v1
5. 결산 재개
6. 원본 회비·지출 수정
7. 최종 마감 v2

고유 조건은 대상 월, 결산 유형과 버전의 조합을 기준으로 한다. 중간 결산 횟수는 최종 마감 버전에 영향을 주지 않는다.

중간 결산은 월을 잠그지 않으므로 별도의 재개 작업이 없다. 기존 중간 결산본은 취소하거나 덮어쓰지 않고 다음 버전을 생성한다.

최종 마감만 대상 월의 활성 최종 마감이 된다. 같은 월에는 활성 최종 마감이 하나만 존재한다. 결산 재개 시 해당 최종 마감본은 삭제하지 않고 재개 상태, 처리자와 처리일시를 기록한다.

## 결산 생성 흐름

### 중간 결산

`중간 결산 생성` 작업은 현재 원본 데이터로 새 중간 결산 스냅샷을 원자적으로 생성한다. 기존 결산 계산기와 월별 장부 계산 계약을 재사용한다.

중간 결산 생성 후에도 다음 작업을 허용한다.

- 회비 등록, 취소와 변경
- 지출 등록, 수정과 삭제
- 새로운 중간 결산 버전 생성
- 최종 마감 실행

### 최종 마감

`최종 마감` 작업은 현재 원본 데이터로 새 최종 마감 스냅샷을 원자적으로 생성한다. 현재 월 마감을 거부하던 날짜 조건은 제거하고 미래 월만 거부한다.

최종 마감 후에는 데이터베이스 경계에서 다음 변경을 차단한다.

- 해당 귀속월의 회비 등록, 취소와 변경
- 해당 사용월의 지출 등록, 수정과 삭제

애플리케이션 화면의 버튼 숨김이나 비활성화만으로 잠금을 구현하지 않는다. 직접 API 또는 다른 쓰기 경로에서도 같은 규칙이 적용되도록 데이터베이스가 활성 최종 마감 존재 여부를 검증한다.

회원 가입일, 활동 시작 월, 휴회와 탈퇴 정보의 이후 변경은 기존 불변 스냅샷을 다시 계산하지 않는다. 최종 마감본과 PDF는 생성 당시 값으로 유지한다.

### 결산 재개와 재마감

활성 최종 마감을 재개하면 해당 월의 회비·지출 잠금이 해제된다. 이후 원본을 수정하고 다시 최종 마감하면 다음 최종 마감 버전을 생성한다.

이후 월에 활성 최종 마감이 있으면 이전 월을 재개할 수 없다. 운영자는 최신 최종 마감 월부터 역순으로 재개해야 하며, 기존 기초·기말 장부 연결 규칙을 유지한다.

## 화면 구성

주요 메뉴의 `정산`을 `결산`으로 변경한다. 관련 사용자 문구도 다음처럼 통일한다.

- `월별 정산` → `월별 결산`
- `정산 요약` → `결산 요약`
- `정산 마감` → `최종 마감`
- `정산 재개` → `결산 재개`
- 정산 관련 안내와 오류 → 결산 용어

결산 화면은 다음 영역을 제공한다.

1. 현재 원본 데이터 기준 결산 미리보기
2. `중간 결산 생성`과 `최종 마감` 작업
3. 활성 최종 마감 정보
4. 중간 결산 이력
5. 최종 마감 이력

각 이력 행에는 결산 유형, 버전, 처리자, 처리일시, 상태와 PDF 다운로드를 표시한다. 최신 버전을 먼저 보여주며 과거 버전도 계속 다운로드할 수 있다.

활성 최종 마감이 있는 월의 회비·지출 화면에서는 변경 작업을 제공하지 않는다. 직접 URL이나 동시 요청으로 변경을 시도하면 데이터베이스 오류를 사용자용 안내로 변환한다.

## PDF

중간 결산과 최종 마감 PDF는 스냅샷 생성 당일부터 즉시 다운로드할 수 있다. 기존의 다음 달 1일 다운로드 제한은 제거한다.

PDF는 다음 정보를 명확히 표시한다.

- 제목: `JW 테니스클럽 월간 결산 보고서`
- 대상 월
- `중간 결산` 또는 `최종 마감`
- 유형별 버전
- 처리자와 처리일시
- PDF 생성자와 생성일시
- 기존 회원·회비·미납·지출·장부 지표

파일명은 유형과 버전을 포함한다.

- `jw-tennis-club-2026-07-interim-v1.pdf`
- `jw-tennis-club-2026-07-final-v1.pdf`

각 다운로드 링크는 월만이 아니라 정확한 스냅샷 ID 또는 유형·버전을 지정한다. 재개된 최종 마감본도 감사 이력에서 다운로드할 수 있으며 PDF와 화면에 `재개됨` 상태를 표시한다.

PDF 생성은 선택한 스냅샷의 존재, 요청 운영자의 활성 상태와 접근 권한을 원자적으로 검증하고 감사 로그를 기록한 뒤 응답한다.

## 권한과 감사

새 권한을 추가하지 않고 기존 권한을 재사용한다.

- 중간 결산과 최종 마감: `settlements.close`
- 결산 재개: `settlements.reopen`
- PDF 다운로드: 모든 활성 운영자

감사 로그에는 스냅샷 ID, 대상 월, 결산 유형, 버전, 작업자와 작업일시를 기록한다.

주요 감사 작업은 다음과 같다.

- `monthly_settlement.interim_created`
- `monthly_settlement.closed`
- `monthly_settlement.reopened`
- `monthly_report.generated`

기존 내부 식별자의 `settlement` 명칭은 유지하되 사용자에게 표시하는 문구는 `결산`으로 변환한다.

## 오류 처리

사용자에게 다음 실패 원인을 구체적으로 안내한다.

- 미래 월은 결산할 수 없음
- 이미 활성 최종 마감이 있는 월을 다시 최종 마감할 수 없음
- 최종 마감된 월의 회비·지출은 변경할 수 없음
- 변경하려면 먼저 결산을 재개해야 함
- 선택한 결산 유형·버전 또는 스냅샷을 찾을 수 없음
- 권한이 없거나 비활성 운영자임
- 직전 월의 활성 최종 마감이 없어 장부 잔액을 연결할 수 없음
- 계산 불변식 또는 활동 시작 월 완전성 검증 실패

동시 중간 결산 요청은 유형별 버전 충돌 없이 직렬화한다. 동시 최종 마감 요청은 하나의 활성 최종 마감만 생성한다. 결산 생성과 원본 변경이 경합하면 월별 잠금과 원본 테이블 잠금으로 스냅샷 경계를 보장한다.

## 데이터베이스 배포

기존 운영 마이그레이션을 수정하지 않고 추가형 마이그레이션을 만든다.

추가형 마이그레이션은 다음을 수행한다.

- 결산 유형 컬럼과 제약 추가
- 기존 스냅샷을 `final`로 백필
- 유형별 버전 고유 조건 적용
- 활성 최종 마감 전용 부분 고유 인덱스 적용
- 중간 결산 생성 RPC 추가
- 현재 월 최종 마감을 허용하도록 최종 마감 RPC 교체
- 정확한 스냅샷을 검증·감사하는 PDF RPC 교체
- 최종 마감 월의 회비·지출 변경 차단
- PostgREST 스키마 캐시 갱신

운영 적용 전에 기존 `monthly_closings` 행의 유형, 버전과 활성 상태가 새 제약을 만족하는지 검증한다.

## 검증

### 버전과 상태

- 첫 중간 결산은 중간 결산 v1이다.
- 다음 중간 결산은 중간 결산 v2이며 v1은 유지된다.
- 중간 결산이 존재해도 첫 최종 마감은 최종 마감 v1이다.
- 재개 후 재마감은 최종 마감 v2이며 이전 최종 마감본은 유지된다.
- 같은 월에 활성 최종 마감은 하나만 존재한다.

### 변경 잠금

- 중간 결산 후 회비와 지출의 생성·수정·취소·삭제가 가능하다.
- 최종 마감 후 같은 월의 회비와 지출 변경을 모든 쓰기 경로에서 거부한다.
- 결산 재개 후 회비와 지출 변경이 다시 가능하다.
- 다른 월의 회비와 지출은 영향을 받지 않는다.

### PDF

- 중간 결산과 최종 마감 PDF를 생성 당일 다운로드할 수 있다.
- PDF 요청은 지정한 스냅샷 버전을 정확히 사용한다.
- 이후 원본 변경이 과거 중간 결산 PDF를 바꾸지 않는다.
- 결산 유형, 유형별 버전, 처리자, 처리일시와 상태가 PDF에 표시된다.
- PDF 생성 감사 로그가 정확한 스냅샷 ID와 유형을 기록한다.

### 화면과 용어

- 메뉴, 화면 제목, 버튼, 안내, 오류와 PDF에서 사용자용 `정산` 문구가 남지 않는다.
- 내부 DB·RPC·코드 식별자의 `settlement` 명칭은 유지된다.
- 결산 이력은 최신순이며 모든 과거 버전의 PDF 링크를 제공한다.
- 활성 최종 마감이 있는 월의 회비·지출 변경 UI를 제공하지 않는다.

### 권한·동시성·회귀

- 중간 결산과 최종 마감은 `settlements.close` 권한을 요구한다.
- 결산 재개는 `settlements.reopen` 권한을 요구한다.
- 모든 활성 운영자는 허용된 결산 PDF를 다운로드할 수 있다.
- 동시 중간 결산과 동시 최종 마감 요청이 중복 버전이나 중복 활성 마감을 만들지 않는다.
- 직전 월 기말 잔액과 다음 월 기초 잔액 연결, 미납 계산, 활동 시작 월 경계와 스냅샷 개인정보 제외 규칙을 유지한다.

## 범위 제외

- 내부 `settlement` 식별자와 기존 데이터베이스 객체의 전면 이름 변경
- 중간 결산 스냅샷 삭제 또는 취소
- 중간 결산 후 원본 입력 잠금
- 미래 월 결산
- PDF에 회원 이름, 회원번호나 개인별 납부 내역 추가
