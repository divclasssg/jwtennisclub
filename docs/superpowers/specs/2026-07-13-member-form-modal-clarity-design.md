# 회원 등록·수정 모달 명확성 개선 설계

## 목표

회원 등록과 수정 폼에서 각 입력 항목의 의미를 바로 이해할 수 있도록 화면에 label을 표시하고, 텍스트 입력에는 유용한 예시 placeholder를 제공한다. 회원 수정은 목록에서 이동할 때뿐 아니라 수정 URL을 직접 열거나 새로고침할 때도 팝업 형태로 표시한다.

## 범위

- 회원 등록과 회원 수정에서 사용하는 `MemberForm`
- 회원 수정 직접 라우트 `/members/[id]/edit`
- 회원 목록에서 수정 링크를 따라갈 때 사용하는 인터셉트 모달 라우트
- 관련 컴포넌트 및 라우트 테스트

회원 외의 회비·지출·일정 폼 스타일과 데이터 저장 규칙은 변경하지 않는다.

## UI 설계

- `이름`, `연락처`, `그룹`, `가입일`, `상태`, `탈퇴일`, `메모` label을 입력 컨트롤 위에 항상 표시한다.
- 이름 placeholder는 `홍길동`, 연락처 placeholder는 기존 `010-1234-5678`, 메모 placeholder는 `특이사항을 입력하세요`로 표시한다.
- select와 날짜 input은 브라우저 기본 동작과 화면 label만 사용한다. 선택값이나 날짜 형식을 흉내 내는 placeholder는 추가하지 않는다.
- 연락처 관리 권한이 없는 수정 화면은 현재처럼 마스킹된 연락처를 읽기 전용으로 표시하며 `연락처` 제목을 유지한다.
- label과 컨트롤 사이의 간격에는 기존 전역 디자인 토큰을 사용한다.

## 컴포넌트 설계

공통 `FormField`에 label을 시각적으로 표시할 수 있는 명시적 옵션을 추가한다. 기본값은 현재의 스크린 리더 전용 label로 유지하고, `MemberForm`에서만 시각적 label 옵션을 활성화한다. 이렇게 하면 다른 기능의 조밀한 폼 레이아웃은 바뀌지 않는다.

회원 수정 데이터 로딩과 오류 메시지, `MemberForm` 렌더링은 재사용 가능한 수정 콘텐츠 컴포넌트로 분리한다. 직접 수정 페이지와 인터셉트 라우트는 이 콘텐츠를 동일한 `회원 수정` 모달에 담아 렌더링한다.

## 라우팅 동작

- 회원 목록에서 `/members/[id]/edit`로 클라이언트 이동하면 `@modal/(.)members/[id]/edit`가 회원 목록 위에 수정 모달을 표시한다.
- 같은 URL을 직접 열거나 새로고침하면 `/members/[id]/edit/page.tsx`가 앱 셸 안에서 수정 모달을 표시한다.
- 모달 닫기와 취소는 기존 회원 등록 모달과 같은 `/members` 복귀 동작을 사용한다.
- 수정 권한이 없거나 회원이 존재하지 않으면 기존과 동일하게 404 처리한다.

## 데이터와 오류 처리

기존 `updateMember` 서버 액션, 회원 조회, 그룹 조회, 권한 검사, 중복 확인 토큰과 오류 문구를 유지한다. 이번 변경은 표현과 라우팅에만 국한하며 회원 데이터 모델이나 저장 형식은 바꾸지 않는다.

## 테스트 및 검증

TDD 순서로 다음 기대 동작을 먼저 테스트에 추가한다.

1. 회원 등록·수정 폼의 label이 화면 표시용 스타일로 렌더링된다.
2. 이름, 연락처, 메모에 지정한 placeholder가 존재한다.
3. 인터셉트 수정 라우트가 `회원 수정` dialog와 기존 회원 값을 렌더링한다.
4. 직접 수정 라우트도 `회원 수정` dialog를 렌더링한다.
5. 권한과 기존 중복 확인 제출 동작이 유지된다.

집중 테스트를 통과한 뒤 전체 테스트, lint, TypeScript typecheck, Next.js production build를 실행한다.

## 완료 기준

- 등록·수정 폼의 모든 입력 항목을 보이는 label로 구분할 수 있다.
- 텍스트 입력에서 예시 또는 입력 목적을 placeholder로 확인할 수 있다.
- 목록 이동, 직접 접속, 새로고침 모두 회원 수정이 팝업 형태로 보인다.
- 회원 외 폼의 label 표시 방식은 바뀌지 않는다.
- 기존 회원 권한, 저장, 중복 확인 동작에 회귀가 없다.
