# 월간 정산 마감 및 PDF 회비 현황 설계

## 목표

회원 공유용 월간 정산 PDF에 해당 월의 회원·회비·미납·누적 장부 현황을 개인 식별 정보 없이 제공한다. PDF는 현재 데이터를 매번 재계산하지 않고 운영자가 확정한 정산 마감 스냅샷을 사용한다.

## 범위

이번 작업에 다음 기능을 포함한다.

- 회원의 가입일과 활동 시작 월 분리
- 활동 시작 월을 회비, 정모 명단과 월별 활동 회원 집계에 적용
- 회원별 완납·부분납부·미납·초과납부 계산
- 월별 정산 마감, 재개와 버전이 있는 불변 스냅샷
- 2026년 7월부터 이어지는 기초·기말 장부 잔액
- 마감 스냅샷만 사용하는 회원 공유용 PDF
- 마감·재개·PDF 생성 감사 로그

회원 이름, 회원번호, 개인별 납부 상태, 개인별 납부 금액, 영수증, 내부 회비·지출 메모는 PDF에서 계속 제외한다.

## 확정한 접근

정산 화면과 PDF가 같은 공유 계산기를 사용한다. 마감 전에는 현재 원본 데이터를 사용해 미리보기를 제공하고, 마감 시 데이터베이스 RPC가 같은 계산 계약으로 한 시점의 스냅샷을 원자적으로 생성한다.

PDF는 활성 마감 스냅샷만 읽는다. 회원 상태, 기준 회비, 납부 기록 또는 지출이 나중에 변경되어도 기존 PDF 숫자는 바뀌지 않는다. 변경을 반영하려면 해당 월을 재개하고 다시 마감해 새 버전을 생성해야 한다.

PDF 전용 계산과 다운로드 시점의 원본 데이터 재조회는 사용하지 않는다.

## 회원 생명주기

### 가입일과 활동 시작 월

회원은 다음 두 시점을 별도로 저장한다.

- 가입일: 행정상 회원으로 등록된 날짜
- 활동 시작 월: 실제 클럽 활동과 회비·정모 대상이 시작되는 월의 첫날

`members.activity_start_month`는 월의 첫날만 허용하며 가입일이 속한 월보다 빠를 수 없다. 신규 회원 등록·수정 화면은 두 값을 모두 받는다.

활동 시작 월이 미래인 회원은 회원 명단에 유지하되 `활동 예정`으로 표시한다. 활동 시작 월은 다음 기능의 공통 시작 기준이다.

- 월말 활동 회원 수
- 회비 청구 대상
- 준비 중인 정모 월 명단과 최초 잠금 명단

이미 잠긴 정모 명단, 기존 출석 행과 이미 마감된 정산 스냅샷은 활동 시작 월을 변경해도 다시 쓰지 않는다.

### 기존 회원 전환

가입일만으로 활동 시작 월을 추정하지 않는다. 기존 회원의 활동 시작 월은 운영자가 확인한 값으로 백필한다.

전환 중에는 컬럼을 nullable로 추가하되 신규 등록·수정은 값을 필수로 받는다. 마감 대상 월에 생명주기가 겹치는 회원 중 활동 시작 월이 비어 있으면 정산 마감을 거부한다. 전체 백필 검증 후 별도 제약으로 `NOT NULL`을 적용한다.

## 월별 회원 및 회비 기준

### 월말 활동 회원 수

다음 조건을 모두 만족하는 회원 수다.

- 활동 시작 월이 대상 월과 같거나 이전이다.
- 탈퇴일이 없거나 대상 월 말일보다 뒤다.
- 대상 월에 휴회 상태가 아니다.

회비 면제 회원번호 `#0000`은 활동 회원 수에 포함한다.

### 회비 청구 대상 회원

월말 활동 회원 중 회비 면제 회원번호 `#0000`을 제외한 회원이다. 활동 시작 월부터 기준 회비 전액을 부과하며 일할 계산은 하지 않는다.

휴회 시작 월부터 회비 대상에서 제외한다. 이미 저장된 납부 기록과 마감 스냅샷은 회원 생명주기 변경으로 삭제하거나 다시 계산하지 않는다.

현재 기준 월 회비는 `DEFAULT_MONTHLY_FEE_AMOUNT`의 30,000원이다. 마감 스냅샷은 대상 월에 적용한 기준 회비도 함께 저장하므로 이후 상수 변경이 과거 보고서에 영향을 주지 않는다.

## 납부와 미납 계산

계산은 회비 대상 회원별로 수행한다.

- 완납 회원: 해당 월 납부액이 기준 회비 이상인 회원
- 미납 회원: 납부액이 기준 회비보다 적은 회원. 납부 기록이 없는 회원과 부분납부 회원을 모두 포함한다.
- 개인 인정 납부액: `min(개인 납부액, 기준 회비)`
- 개인 미납액: `max(기준 회비 - 개인 납부액, 0)`
- 총 청구액: 대상 회원별 기준 회비의 합
- 인정 납부액: 개인 인정 납부액의 합
- 미납액: 개인 미납액의 합

초과납부는 다른 회원의 미납액과 상계하지 않는다.

### 실제 수납액과 조정 수납액

- 실제 회비 수납액: 대상 귀속월의 모든 `fee_payments.amount` 합계
- 조정 수납액: 실제 회비 수납액에서 인정 납부액을 뺀 금액

조정 수납액에는 대상 회원의 초과납부와 비대상 회원의 귀속월 납부가 포함된다. 값이 0원이 아니면 PDF에 별도 항목으로 표시한다.

다음 등식을 유지한다.

`실제 회비 수납액 = 인정 납부액 + 조정 수납액`

운영 지출과 당월 귀속 수지는 실제 회비 수납액을 사용한다. 미납액은 회원별 인정 납부액을 기준으로 계산한다.

## 회계 기준

- 회비 수입, 납부와 미납은 `fee_payments.period_month`인 귀속월 기준이다.
- 지출은 `expenses.expense_date`인 사용일 기준이다.
- 기존 `월 순변동` 명칭은 `당월 귀속 수지`로 변경한다.
- 당월 귀속 수지는 `실제 회비 수납액 - 운영 지출`이다.

마감 후 입력한 지연 납부는 기존 스냅샷에 자동 반영하지 않는다. 반영하려면 정산을 재개하고 다시 마감해야 한다. PDF에는 회비는 귀속월, 지출은 사용일 기준이라는 안내를 표시한다.

## 정산 마감과 스냅샷

### 시작 월과 장부 잔액

장부 시작 월은 2026년 7월이다.

- 2026년 7월 기초 장부 잔액은 0원이다.
- 기말 장부 잔액은 `기초 장부 잔액 + 당월 귀속 수지`다.
- 2026년 8월부터 기초 장부 잔액은 직전 월의 활성 마감 스냅샷에 저장된 기말 장부 잔액이다.

따라서 2026년 7월에 남은 금액은 7월 기말 장부 잔액이자 8월 기초 장부 잔액이다. 이 값은 은행 계좌 잔액이 아니라 현재 시스템이 추적하는 회비 수입과 운영 지출만 반영한 장부 잔액이다.

### 마감 순서

- 2026년 7월을 먼저 마감한다.
- 2026년 8월 이후 월은 직전 월에 활성 마감 스냅샷이 있어야 마감할 수 있다.
- 미래 월과 아직 끝나지 않은 현재 월은 마감할 수 없다.
- 마감 시 회원, 회비, 지출 원본을 한 트랜잭션에서 읽고 스냅샷을 생성한다.
- 같은 월에 활성 마감 스냅샷은 하나만 존재한다.

### 스냅샷 내용

각 스냅샷은 최소한 다음 값을 저장한다.

- 대상 월과 버전
- 마감일시와 마감 처리자
- 적용한 기준 회비
- 월말 활동 회원 수
- 회비 대상·완납·미납 회원 수
- 총 청구액, 실제 회비 수납액, 인정 납부액, 조정 수납액과 미납액
- 운영 지출 합계와 지출 건수
- 카테고리별 지출 건수·금액
- 회원 공유용 전체 지출 내역의 사용일·카테고리·내용·금액
- 당월 귀속 수지
- 기초·기말 장부 잔액

스냅샷에는 PDF에 포함하지 않는 회원 이름, 회원번호, 개인별 납부 내역, 영수증과 내부 메모를 저장하지 않는다. 운영 감사에 필요한 원본 변경 이력은 기존 원본 테이블과 `audit_logs`에서 관리한다.

### 재개와 재마감

- 활성 마감 스냅샷을 재개하면 그 스냅샷은 삭제하지 않고 재개 상태와 처리자·처리일시를 기록한다.
- 이후 월에 활성 마감 스냅샷이 있으면 과거 월을 재개할 수 없다.
- 운영자는 최신 월부터 역순으로 재개해야 한다.
- 재개 상태에서는 PDF 다운로드를 제공하지 않는다.
- 다시 마감하면 이전 버전을 덮어쓰지 않고 증가한 버전의 새 스냅샷을 생성한다.
- PDF는 최신 활성 마감 버전만 사용한다.

## 권한

- 정산 마감: `settlements.close` 권한이 있는 활성 운영자
- 정산 재개: `settlements.reopen` 권한이 있는 활성 운영자
- PDF 다운로드: 기존 제품 결정대로 모든 활성 운영자

마감·재개는 데이터베이스 RPC가 인증 사용자, 활성 프로필과 권한을 직접 검증한 후 실행한다. PDF 다운로드는 원본 회원·회비·지출 테이블을 조회하지 않고 활성 마감 스냅샷만 읽는다.

비로그인 사용자는 로그인 화면으로 이동한다. 비활성 계정과 비운영자는 PDF를 받을 수 없으며, 부분 권한이나 RLS의 빈 결과를 정상적인 0명·0원 보고서로 해석하지 않는다.

마감, 재개와 PDF 생성은 `audit_logs`에 대상 월, 스냅샷 버전, 작업자와 작업일시를 기록한다.

## PDF 생성 조건

- 대상 월에 활성 마감 스냅샷이 있어야 한다.
- 대상 월의 다음 달 1일 00:00 이후부터 생성할 수 있다.
- 재개 상태에서는 생성할 수 없다.
- 모든 숫자와 지출 행은 최신 활성 스냅샷에서 읽는다.

파일명은 기존 `jw-tennis-club-YYYY-MM-report.pdf` 형식을 유지한다.

## PDF 구성

PDF에는 다음 내용을 표시한다.

- 제목: `YYYY년 M월 테니스 클럽 월간 정산 보고서`
- 마감 버전, 마감일과 마감 처리자
- PDF 생성일과 생성자
- 월말 활동 회원 수와 회비 대상 회원 수
- 완납 회원 수와 미납 회원 수
- 총 청구액, 실제 회비 수납액, 인정 납부액, 미납액
- 조정 수납액이 0원이 아닐 때 조정 수납액
- 운영 지출
- 당월 귀속 수지
- 기초·기말 장부 잔액
- 카테고리별 지출 건수와 금액
- 전체 지출 내역의 사용일, 카테고리, 내용과 금액
- 회비는 귀속월, 지출은 사용일 기준이라는 안내
- 개인별 납부 내역, 미납 회원명, 영수증 원본과 내부 메모를 제외했다는 안내

기존 `주요 지출 내역`은 실제로 대상 월의 모든 지출을 표시하므로 `지출 내역`으로 이름을 변경한다.

각 지표는 완전한 항목명과 값의 쌍으로 표시한다. 색상이나 위치에만 의존하지 않으며, 읽기와 텍스트 추출 순서를 `항목명 → 값`으로 유지한다.

회비 대상 회원이 0명이면 관련 인원과 금액을 모두 0으로 표시하고 `해당 월 회비 부과 대상 회원이 없습니다` 안내를 추가한다.

## 정산 화면

마감 전에는 현재 원본 데이터로 계산한 미리보기를 표시한다. 마감 버튼을 누르기 전에 활동 시작 월 누락, 직전 월 미마감, 현재·미래 월, 계산 불일치와 권한 오류를 검증한다.

마감 후에는 스냅샷 버전, 마감일, 마감 처리자와 확정된 요약을 표시한다. 권한에 따라 정산 재개 작업을 제공한다. PDF 다운로드는 생성 가능 날짜와 활성 마감 상태를 모두 만족할 때만 제공한다.

## 오류 처리와 불변식

- 활동 시작 월이 필요한 회원에게 값이 없으면 마감을 거부한다.
- 회원별 계산 합계가 총 청구액·인정 납부액·미납액과 일치하지 않으면 마감을 거부한다.
- 실제 회비 수납액이 인정 납부액과 조정 수납액의 합과 다르면 마감을 거부한다.
- 직전 월 기말 잔액과 현재 월 기초 잔액이 다르면 마감을 거부한다.
- 마감 RPC는 동시 요청을 직렬화하고 같은 월의 중복 활성 스냅샷을 만들지 않는다.
- PDF 조회 중 스냅샷이 없거나 재개 상태이면 오류 응답을 반환한다.
- 원본 조회 권한 문제를 0건 데이터로 간주하지 않는다.

## 테스트

### 회원과 활동 시작 월

- 가입 월과 활동 시작 월을 따로 저장한다.
- 활동 시작 월이 가입 월보다 빠르면 거부한다.
- 활동 시작 전 회원을 회비와 준비 중 정모 명단에서 제외한다.
- 활동 시작 월부터 회비와 준비 중 정모 명단에 포함한다.
- 잠긴 정모 명단과 기존 출석은 다시 쓰지 않는다.
- 기존 회원의 활동 시작 월이 비어 있으면 정산 마감을 거부한다.

### 회비 계산

- 미납, 부분납부, 완납과 초과납부 회원을 구분한다.
- 부분납부 회원을 미납 회원 수에 포함한다.
- 회원별 미납액을 합산한다.
- 한 회원의 초과납부가 다른 회원의 미납을 상쇄하지 않는다.
- 비대상 납부와 초과납부를 조정 수납액에 포함한다.
- 실제 수납액과 인정 납부액·조정 수납액 등식을 검증한다.
- 회비 대상이 0명인 월을 0으로 계산한다.

### 마감과 잔액

- 2026년 7월 기초 잔액을 0원으로 고정한다.
- 직전 월 기말 잔액을 다음 월 기초 잔액으로 승계한다.
- 직전 월 미마감, 현재·미래 월과 중복 마감을 거부한다.
- 이후 월이 마감된 과거 월 재개를 거부한다.
- 최신 월부터 역순으로 재개할 수 있다.
- 재마감 시 버전이 증가하고 이전 스냅샷이 보존된다.
- 원본 변경이 기존 스냅샷과 PDF를 바꾸지 않는다.
- 동시 마감 요청이 하나의 활성 스냅샷만 생성한다.

### 권한과 PDF

- 마감·재개 권한 조합을 RPC와 RLS에서 검증한다.
- 모든 활성 운영자가 활성 마감 PDF를 받을 수 있다.
- 비로그인, 비활성과 비운영자 접근을 거부한다.
- 마감 전, 재개 상태와 다음 달 1일 전 다운로드를 거부한다.
- PDF가 원본 테이블을 다시 조회하지 않는지 검증한다.
- 마감 버전·처리자·처리일, 회원·회비·잔액 지표와 전체 지출 내역을 렌더링한다.
- 회원 이름, 회원번호, 개인별 납부 내역, 영수증과 내부 메모를 포함하지 않는다.
- 마감·재개·PDF 생성 감사 로그를 검증한다.

## 배포 순서

1. 활동 시작 월과 정산 스냅샷 스키마, RPC와 RLS를 배포한다.
2. 기존 회원의 활동 시작 월을 운영자가 확인한 값으로 백필한다.
3. 백필 완전성과 월 첫날·가입 월 경계 제약을 검증한다.
4. 앱의 회원·회비·정모·정산·PDF 코드를 배포한다.
5. 2026년 7월부터 월별로 순서대로 정산을 검토하고 마감한다.
6. 전체 백필과 운영 검증 후 활동 시작 월 `NOT NULL` 제약을 적용한다.

정산 마감 전에는 PDF 다운로드를 제공하지 않는다.
