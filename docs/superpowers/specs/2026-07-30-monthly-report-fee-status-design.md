# 월간 정산 PDF 회비 현황 설계

## 목표

회원 공유용 월간 정산 PDF에 해당 월의 회비 청구 및 미납 규모를 개인 식별 정보 없이 추가한다.

## 범위

PDF의 정산 요약에 다음 여섯 지표를 표시한다.

- 회비 대상 회원 수
- 납부 회원 수
- 미납 회원 수
- 총 청구액
- 납부액
- 미납액

회원 이름, 회원번호, 개인별 납부 여부와 내부 회비 메모는 계속 제외한다.

이번 변경은 현재 데이터로 PDF를 생성하는 기존 구조를 유지한다. 정산 마감, 월별 스냅샷 저장, 감사 로그는 아직 앱에 구현되어 있지 않으므로 이 작업에서 새 데이터베이스 구조나 마감 흐름을 만들지 않는다.

## 검토한 접근안

### 1. 현재 회비 화면의 계산 규칙 재사용

PDF 생성 시 해당 월의 회비 대상 회원과 납부 기록을 함께 조회하고 기존 회비 요약 계산기를 사용한다.

- 장점: 회비 화면과 PDF가 같은 숫자를 표시하며 변경 범위가 작다.
- 단점: 과거 월을 다시 생성하면 당시 데이터가 아니라 현재 데이터와 코드에 따라 값이 달라질 수 있다.

이 접근을 채택한다.

### 2. PDF 전용 계산 구현

보고서 코드에서 회원 수와 미납액을 별도로 계산한다.

- 장점: 보고서 코드만 수정할 수 있다.
- 단점: 회비 화면과 계산 규칙이 중복되어 두 화면의 숫자가 달라질 위험이 있다.

중복 계산 때문에 채택하지 않는다.

### 3. 정산 마감 스냅샷 도입

월을 마감할 때 회비 대상 수, 청구액, 납부액과 미납액을 저장하고 PDF는 저장된 값을 읽는다.

- 장점: 과거 보고서가 이후 회원 상태나 기준 회비 변경에 영향받지 않는다.
- 단점: 현재 없는 마감 상태, 권한, 재마감, 감사 로그와 데이터 마이그레이션을 함께 설계해야 한다.

장기적으로 가장 안전하지만 이번 PDF 보강 범위를 크게 넘으므로 후속 작업으로 분리한다.

## 계산 기준

### 회비 대상 회원

기존 회비 화면과 동일하게 다음 조건을 모두 만족하는 회원이다.

- 해당 월 말일까지 가입했다.
- 현재 활동 중이거나, 휴회 시작 월이 해당 월보다 뒤다.
- 회비 면제 회원번호 `#0000`이 아니다.

검색어 같은 화면 전용 필터는 PDF 계산에 적용하지 않는다.

### 납부와 미납

- 납부 회원 수: 회비 대상 회원 중 해당 월의 `fee_payments` 기록이 있는 회원 수
- 미납 회원 수: 회비 대상 회원 수에서 납부 회원 수를 뺀 값
- 총 청구액: 회비 대상 회원 수 × 기준 월 회비
- 납부액: 회비 대상 회원의 해당 월 납부 기록 금액 합계
- 미납액: 총 청구액에서 납부액을 뺀 값이며, 초과 납부가 있어도 음수로 표시하지 않고 0원으로 제한

현재 기준 월 회비는 기존 `DEFAULT_MONTHLY_FEE_AMOUNT` 값인 30,000원을 사용한다.

회비 대상이 아닌 회원의 과거 납부 기록은 기존 회비 수입 합계에는 포함되지만, 납부 회원 수와 납부액 및 미납액 계산에서는 제외한다. 이 차이가 실제 데이터에서 발생하면 운영 데이터 정합성 문제이므로 후속 검증 대상으로 다룬다.

## 데이터 흐름

1. 월간 PDF 라우트가 대상 월의 회비 납부 기록과 지출 내역을 조회한다.
2. 같은 라우트가 회비 화면과 동일한 조건으로 대상 회원 ID를 조회한다.
3. 보고서 데이터 조립 함수가 기존 정산 합계와 회비 요약을 생성한다.
4. PDF 템플릿이 여섯 회비 지표를 회원 식별 정보 없이 표시한다.

## PDF 구성

기존 제목, 생성일, 생성자, 정산 요약, 카테고리별 지출, 주요 지출 내역과 제외 안내문을 유지한다.

정산 요약에는 기존 회비 수입, 운영 지출, 월 순변동 아래에 회비 현황 영역을 추가한다. 회비 현황은 인원 세 항목과 금액 세 항목을 명시적으로 구분한다.

## 오류 처리

회비 대상 회원 조회에 실패하면 잘못된 숫자의 PDF를 생성하지 않고 보고서 요청을 실패시킨다. 기존 인증 및 회비·지출 조회 오류 처리 방식은 유지한다.

## 테스트

- 보고서 데이터 단위 테스트에서 회비 대상·납부·미납 인원과 총 청구액·납부액·미납액을 검증한다.
- 초과 납부 시 미납액이 0원보다 작아지지 않는지 검증한다.
- PDF 렌더 테스트 입력에 신규 지표를 포함해 PDF 버퍼 생성 회귀를 검증한다.
- 라우트 테스트에서 대상 회원 조회와 보고서 데이터 전달을 검증한다.
- 기존 회원 이름, 개인별 납부 내역과 내부 메모가 보고서 데이터에 추가되지 않았는지 유지한다.

## 후속 과제

정산 마감 기능을 구현할 때 월별 회비 의무와 정산 합계를 스냅샷으로 저장하고, PDF가 마감 스냅샷만 사용하도록 전환한다. 그때 기준 회비도 효력 시작 월을 가진 데이터로 관리해야 한다.
