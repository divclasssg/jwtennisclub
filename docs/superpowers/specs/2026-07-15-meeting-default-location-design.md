# 정모 기본 장소 설계

## 목표

정모 장소의 기본값을 `용마테니스장`으로 통일한다. 기존 장소 미정 데이터와 앞으로 생성되는 정기 정모·대체 번개 모두 같은 규칙을 사용하며, 운영자는 필요할 때 다른 장소로 변경할 수 있다.

## 데이터 규칙

- `club_meetings.location`의 데이터베이스 기본값은 `용마테니스장`이다.
- 기존 `location is null` 행은 `용마테니스장`으로 일괄 보정한다.
- 보정 후 `location`은 `not null`로 제한해 화면과 데이터가 다시 어긋나지 않게 한다.
- 기존 1~200자 길이 검증은 유지한다.
- 장소 변경 요청이 비어 있거나 공백뿐이면 장소를 제거하지 않고 `용마테니스장`으로 저장한다.

## 생성 및 변경 흐름

- 자동 생성 정기 정모는 컬럼 기본값을 사용한다.
- 대체 번개 생성은 입력 장소가 비어 있으면 `용마테니스장`을 사용하고, 값이 있으면 공백을 제거한 입력값을 사용한다.
- 기존 정기 정모 장소 변경 기능은 유지하며, 다른 유효한 장소를 저장할 수 있다.
- 장소가 실제로 바뀐 경우에만 기존 `location_updated` 생명주기 이벤트를 기록한다.

## 화면 계약

- 목록, 모바일 카드, 명단 모달과 일정 화면은 DB의 장소 문자열을 그대로 표시한다.
- 마이그레이션 이후 정상 데이터에는 `미정` 또는 `장소 미정` 대체 문구가 나타나지 않는다.
- 타입과 화면의 기존 null 방어 처리는 배포 순서 호환을 위해 유지할 수 있지만, 신규 DB 계약은 null을 생성하지 않는다.

## 마이그레이션

- 성능 최적화 마이그레이션 `202607150003_optimize_meeting_directory_load.sql`과 분리된 후속 마이그레이션을 추가한다.
- 마이그레이션 순서는 기존 null 보정, 컬럼 기본값 설정, `not null` 제약 적용, 장소 변경·대체 번개 RPC 교체 순이다.
- RPC의 `security definer`, 빈 `search_path`, 기존 실행 권한 경계는 그대로 유지한다.

## 검증

- 마이그레이션 정적 테스트로 보정 순서, 기본값, `not null`, RPC 보안과 빈 입력 처리 규칙을 확인한다.
- 정기 정모 자동 생성과 대체 번개 생성 SQL이 기본 장소를 사용하는지 확인한다.
- 장소 변경 액션 및 목록·모바일·일정 회귀 테스트를 실행한다.
- 전체 테스트, ESLint, TypeScript 검사와 `git diff --check`를 통과시킨다.
- 운영 DB 적용 후 null 장소 0건과 기존·향후 정모의 기본 장소를 확인한다.
