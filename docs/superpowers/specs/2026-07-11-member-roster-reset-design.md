# 회원 명부 초기화 설계

## 목표

Git에서 제외된 로컬 원본 파일 `members/members.csv`를 기준으로 회원 관리를
재구성한다. CSV를 일회성 파괴적 초기화의 최종 명부로 사용하고, 각 회원에게
영구 회원번호를 부여한다. 전체 연락처는 전용 권한으로 분리하고, Group을 회원
속성으로 추가하며, 탈퇴 사유는 완전히 제거한다.

초기화 과정에서 기존 회비 납부 이력과 기존 회원 행은 의도적으로 삭제한다.
지출, 일정, 운영자 로그인 프로필과 그 밖의 관련 없는 운영 데이터는 유지한다.

## 제품 범위

포함 사항:

- CSV `ID`를 기준으로 변경 불가능한 영구 회원번호 저장
- 초기화 이후 신규 회원의 영구 회원번호 자동 발급
- 전체 연락처 저장 및 권한별 전체·마스킹 표시
- Group A, Group B, 미지정 분류
- 회원 등록·수정에서 Group 선택, 회원 목록에서 Group 필터 제공
- DB, 폼, 목록, CSV, 검증, 테스트에서 탈퇴 사유 완전 제거
- 회비 CSV의 회원 식별 기준을 이름과 전화번호 끝 4자리에서 영구 회원번호로 변경
- 스테이징 검증을 거치는 트랜잭션 기반 회원 명부 초기화
- 기존 운영자 프로필을 정규화된 이름으로 새 회원과 재연결

제외 사항:

- 기존 `fee_payments` 보존 또는 마이그레이션
- 원본 CSV에 없는 기존 `members` 행 보존
- 탈퇴 사유, 회비 납부 이력, 기존 회원 명부 백업
- Group 추가·이름 변경·정렬·비활성화 관리 UI
- CSV의 `구분` 또는 `직책`을 권한이나 운영자 프로필의 기준으로 사용
- 실제 회원 데이터를 소스 관리, 마이그레이션, 테스트 픽스처, 로그, 오류 메시지,
  문서에 포함

## 확정된 제품 결정

- CSV `ID`는 영구 비즈니스 식별자이자 CSV 중복 판별의 1차 기준이다.
- 발급된 영구 회원번호는 수정할 수 없다.
- 신규 회원번호는 원본 CSV와 같은 공통 접두어와 숫자 4자리 형식으로 자동 발급한다.
- CSV를 최종 기준으로 사용하며 기존 회비와 회원은 병합하지 않고 삭제한다.
- 기존 운영자 프로필은 정규화된 정확한 이름으로 CSV 회원과 재연결한다.
  누락, 중복, 모호한 연결이 하나라도 있으면 초기화를 중단한다.
- 수동 등록 시 정규화된 이름과 연락처가 모두 같은 기존 회원이 있으면 차단한다.
- 이름은 다르지만 연락처가 같은 경우 경고 후 등록을 허용한다.
- 전체 연락처는 관리자 또는 명시적인 연락처 권한 보유자만 본다.
  일반 운영자는 마스킹된 연락처만 본다.
- Group은 회원 관리에 포함하지만 Group 관리 UI는 후속 작업으로 남긴다.
  초기 Group은 A와 B이며 CSV의 `-`는 미지정으로 처리한다.
- 기존 탈퇴 사유와 해당 값은 백업 없이 삭제한다.

## 원본 CSV 규약

현재 원본의 헤더:

- `ID`
- `이름`
- `전화번호`
- `구분`
- `직책`
- `Group`
- `상태`
- `가입일`

초기화에서는 `ID`, `이름`, `전화번호`, `Group`, `상태`, `가입일`만 사용한다.
`구분`과 `직책`은 무시한다. 운영자 여부와 직책은 기존 `profiles`와
`club_positions`가 계속 관리한다.

파괴적 작업을 시작하기 전에 다음 조건을 모두 검증한다.

- 모든 행의 ID가 공통 접두어와 숫자 4자리 형식이며 비어 있지 않고 고유함
- 파일 전체에서 회원번호 접두어가 하나만 사용됨
- 모든 이름이 비어 있지 않음
- 연락처가 비어 있거나 국내 전화번호 10~11자리로 정규화 가능함
- Group이 A, B, `-` 중 하나임
- 상태가 지원되는 회원 상태로 변환 가능함
- `2026.7.1` 같은 점 구분 가입일이 ISO 날짜로 변환 가능함
- 모든 활성 운영자 프로필이 정규화된 이름으로 CSV 회원 한 명과 정확히 일치함
- 정규화된 이름과 연락처가 모두 같은 중복 행이 없음

검증 결과에는 행 번호, 회원번호, 오류 종류만 포함할 수 있다. 실제 이름이나
연락처 원문은 출력하지 않는다.

## 데이터 모델

### 회원

`members`는 애플리케이션 및 외래키 연결을 위해 내부 UUID 기본키를 유지한다.
업무용 필드는 다음과 같이 구성한다.

- `id uuid primary key`
- `member_code text unique not null`: 영구 회원번호
- `name text not null`
- `group_id uuid null references member_groups(id)`
- `operator_profile_id uuid unique null references profiles(id)`
- `status member_status not null`
- `joined_date date not null`
- `withdrawn_date date null`
- `memo text null`
- 기존 생성자·수정자 및 타임스탬프 필드

전환 완료 후 다음 컬럼을 제거한다.

- `phone_last_four`
- `withdrawal_reason`

탈퇴 상태에는 탈퇴일이 필요하고, 활동 또는 휴회 상태에는 탈퇴일을 허용하지 않는
기존 생명주기 검증은 유지한다. 탈퇴 사유 관련 검증은 모두 제거한다.

### 회원 연락처

1:1 관계의 `member_contacts` 테이블을 추가한다.

- `member_id uuid primary key references members(id) on delete cascade`
- `phone_number text null`
- 기존 방식의 생성자·수정자 및 타임스탬프 필드

연락처는 숫자만 남기도록 정규화해 저장하고 국내 전화번호 표시 형식으로 렌더링한다.
원본 CSV에 연락처가 없는 회원이 있으므로 `null`을 허용한다.

`members.view`만으로는 `member_contacts` 원문을 직접 읽을 수 없다. 전체 연락처
열람에는 `members.contacts.view`, 연락처 변경에는 `members.contacts.manage`
권한이 필요하다. 관리자는 두 권한을 기본으로 받고 일반 운영자는 받지 않는다.

서버 전용 데이터 접근 계층은 권한에 따라 전체 연락처 또는 마스킹 연락처만 반환한다.
일반 운영자용 DTO에는 연락처 원문이 포함되면 안 된다. 원문을 가져온 뒤 UI에서만
마스킹하는 방식은 허용하지 않는다.

### 회원 Group

`member_groups` 기준 테이블을 추가한다.

- UUID 기본키
- 고유하고 안정적인 코드
- 표시 이름
- 활성 상태
- 타임스탬프

A와 B를 초기 데이터로 추가한다. CSV의 `-`는 `group_id = null`로 변환한다.
회원 폼과 목록 필터는 활성 Group을 이 테이블에서 조회한다. 향후 Group은 스키마
변경 없이 마이그레이션 또는 관리자 작업으로 추가할 수 있지만 관리 UI는 이번
범위에 포함하지 않는다.

### 회원번호 자동 발급

동시에 여러 회원을 등록해도 번호가 겹치지 않도록 DB 시퀀스 또는 동일 수준의 잠금된
카운터를 사용한다. 초기화 과정에서 CSV의 단일 접두어를 검증하고 자동 발급용
접두어로 저장하며, 숫자 카운터를 가져온 CSV의 최대 번호 다음 값으로 맞춘다.

번호 생성과 회원 추가는 하나의 트랜잭션에서 실행한다. `member_code`에는 DB 고유
제약을 적용하고 일반 회원 수정 경로에서는 변경할 수 없게 한다.

## 중복 판정 규칙

CSV 가져오기:

- 회원번호가 회원·회비 CSV의 유일한 식별 기준이다.
- 회원번호가 중복되면 파일 전체를 거부한다.
- 일반 회원 CSV 가져오기에서 기존 회원번호가 발견되면 신규 회원이 아니라 중복으로
  처리한다.

수동 회원 등록:

- 후보 이름과 연락처를 정규화한 뒤 비교한다.
- 이름과 연락처가 모두 같으면 등록을 차단한다.
- 이름은 같고 연락처가 다르면 서로 다른 회원으로 등록할 수 있다.
- 이름은 다르고 연락처가 같으면 기존 사용 사실을 안전한 필드로 경고한 뒤 등록을
  허용한다.
- 연락처가 없는 동명이인은 자동으로 같은 회원으로 간주하지 않는다. 첫 제출에서는
  중복 경고 상태를 반환하고, 운영자가 `별도 회원으로 등록`을 선택해 두 번째로
  제출해야 한다.

동시 요청이 중복 검사를 우회하지 못하도록 DB 쓰기 경로에서 검사를 직렬화한다.

## 회원 관리 화면

데스크톱과 모바일 회원 화면에는 다음 정보를 표시한다.

- 영구 회원번호
- 이름
- 연락처
- Group
- 운영자 프로필 연결에서 계산한 구분
- 연결된 프로필에서 계산한 직책
- 상태
- 가입일
- 탈퇴일
- 관리 작업

탈퇴 사유는 모든 화면에서 제거한다.

검색과 필터:

- 일반 GET 검색은 이름과 영구 회원번호만 지원한다.
- Group과 회원 상태는 민감하지 않은 URL 필터로 제공한다.
- 권한자의 정확한 연락처 검색은 POST 서버 액션 또는 권한 검사 RPC로 처리해 전체
  연락처가 브라우저 기록, RSC URL, 로그인 이동 URL에 남지 않게 한다.
- 일반 운영자는 연락처 원문으로 검색할 수 없다.

연락처 표시:

- 관리자와 연락처 열람 권한자는 전체 연락처를 형식화해 본다.
- 일반 운영자는 `010-****-1234` 형태의 마스킹 연락처를 본다.
- 연락처 생성·수정에는 `members.contacts.manage` 권한이 필요하다.
- 연락처는 최소한의 DTO만 반환하는 서버 전용 데이터 접근 경계를 통해 조회한다.

## CSV 작업 흐름

### 일회성 회원 명부 초기화

기존 데이터를 먼저 삭제하지 않고 스테이징 검증을 거친다.

1. Git에서 제외된 로컬 CSV를 읽되 추적 파일로 복사하지 않는다.
2. 각 행을 스테이징 표현으로 정규화한다.
3. CSV 규약과 운영자 연결 조건을 모두 검증한다.
4. 실제 회원정보가 없는 건수 중심 dry-run 결과를 만든다.
5. 명시적인 파괴적 초기화 확인값을 요구한다.
6. 하나의 DB 트랜잭션을 시작한다.
7. 모든 `fee_payments`를 삭제한다.
8. 모든 기존 `members`를 삭제한다. 연락처가 존재하면 함께 삭제한다.
9. 검증된 스테이징 데이터로 Group, 회원, 연락처를 추가한다.
10. 정규화된 이름으로 운영자 프로필을 새 회원과 재연결한다.
11. 회원번호 카운터를 가져온 최대 번호 다음으로 이동한다.
12. 회원 수, 연락처 수, 고유성, 운영자 연결 수를 다시 검증한다.
13. 모든 검증이 성공할 때만 커밋하고 하나라도 실패하면 전부 롤백한다.

초기화 도구는 기본적으로 dry-run만 실행한다. 도구 자체에는 실제 회원 데이터가
포함되지 않으며 원본 값을 로그에 남기지 않는다. 명시적인 확인 없이는 파괴적 실행을
거부한다.

### 이후 회원 CSV 가져오기

새 CSV 헤더를 인식하고 영구 회원번호를 중복 판정 기준으로 사용한다. 연락처는 회원
식별자로 사용하지 않는다. 전체 연락처는 검증 후 권한이 분리된 연락처 쓰기 경로로
저장한다.

### 회비 CSV 가져오기

기존 이름과 `phoneLastFour` 조합 대신 영구 회원번호로 회원을 찾는다. 회비 CSV는
회원번호, 납부월, 금액, 납부일, 선택 메모를 사용한다. 이름은 운영자 확인용으로
표시할 수 있지만 식별 기준으로 사용하지 않는다. 존재하지 않거나 중복된 회원번호가
있으면 납부 기록을 하나도 저장하지 않고 전체 가져오기를 거부한다.

## 권한과 보안

- 기존 `members.view/create/update/delete`는 연락처를 제외한 회원 필드를 관리한다.
- `members.contacts.view`, `members.contacts.manage` 권한을 추가한다.
- 관리자는 새 권한을 모두 기본으로 받는다.
- 일반 운영자는 새 권한을 기본으로 받지 않는다.
- `member_contacts` RLS는 전용 권한을 검사한다.
- 마스킹 연락처는 일반 운영자에게 원문을 반환할 수 없는 제한된 함수 또는 뷰로
  제공한다.
- 전체 연락처는 GET URL, 로그인 이동 URL, 로그, 오류 메시지, 커밋된 테스트 데이터,
  문서에 포함하지 않는다.
- Git에서 제외된 `members/`는 계속 로컬 전용으로 유지하며 스테이징할 수 없다.
- 초기화와 연락처 변경은 인증된 활성 사용자와 서버 측 권한 검사를 모두 요구한다.

## 실패 처리

다음 조건에서는 파괴적 작업을 시작하기 전에 중단한다.

- CSV 행 하나라도 정규화 또는 검증 실패
- ID 누락, 중복, 접두어 혼합 또는 형식 오류
- 지원하지 않는 Group 또는 상태
- CSV에 존재하지 않는 운영자 프로필
- 운영자 이름이 CSV의 0개 또는 여러 행과 일치
- 이름과 연락처가 모두 같은 중복 행
- 스테이징과 최종 결과의 예상 건수가 불일치

삭제와 최종 추가는 하나의 트랜잭션에서 처리한다. 실행 중 실패하면 기존 회원과 회비
이력이 그대로 복구된다. 초기화가 성공적으로 커밋된 이후에는 승인된 범위에서 백업을
제외했으므로 애플리케이션을 통해 기존 회원과 회비를 복구할 수 없다.

오류 메시지는 CSV 행 번호나 회원번호와 작업 가능한 오류 종류만 표시한다. 실제
연락처와 이름은 출력하지 않는다.

## 배포 순서

1. 기존 앱이 동작하는 동안 Group, 영구 회원번호, 연락처, 권한, 번호 발급 구조를
   하위 호환 방식으로 추가한다.
2. 새 구조를 읽고 쓰며 탈퇴 사유와 전화번호 끝 4자리에 의존하지 않는 앱을 배포한다.
3. 회원 명부 초기화 dry-run을 실행해 건수와 운영자 연결을 검토한다.
4. 명시적으로 확인한 트랜잭션 초기화를 실행한다.
5. 회원 수, 전체·마스킹 연락처, 운영자 연결, Group 필터, 다음 번호 자동 발급,
   회비 이력 초기화를 검증한다.
6. `phone_last_four`, `withdrawal_reason`, 기존 제약, 임시 스테이징·초기화 DB 객체를
   제거한다.

이 순서는 앱과 스키마 불일치를 막고, 파괴적 트랜잭션의 사전 검증이 끝날 때까지 기존
데이터를 유지한다.

## 테스트 기준

데이터 및 CSV 파서:

- 실제 값 없이 승인된 한국어 CSV 헤더 파싱
- 점 구분 가입일을 ISO 날짜로 변환
- 빈 연락처와 정상적인 10~11자리 연락처 허용
- 잘못된 연락처, 회원번호, 상태, Group 거부
- 중복 회원번호와 중복 이름·연락처 조합 거부
- CSV `구분`, `직책`을 회원 권한 데이터로 사용하지 않음

회원번호:

- 가져온 번호를 변경 없이 유지
- 설정된 접두어와 숫자 4자리 번호 생성
- 가져온 최대 번호 다음부터 자동 발급
- 동시 등록에서도 중복 번호 방지
- 회원번호 수정 거부

중복 판정:

- 같은 이름·같은 연락처 차단
- 같은 이름·다른 연락처 허용
- 다른 이름·같은 연락처 경고 후 허용
- 연락처 없는 동명이인의 두 번째 제출 명시적 확인

권한:

- 익명 사용자는 회원과 연락처를 읽을 수 없음
- 일반 운영자는 연락처 원문을 직접 조회할 수 없음
- 일반 운영자 DTO에는 마스킹 연락처만 포함
- 관리자와 연락처 열람 권한자는 전체 연락처 조회
- 연락처 관리 권한자만 연락처 생성·수정
- 회원 GET URL, 로그인 이동 URL, 회비 데이터에 전체 연락처가 포함되지 않음

초기화:

- dry-run은 DB를 변경하지 않음
- 잘못된 행이 있으면 삭제하지 않음
- 운영자 연결이 누락되거나 모호하면 삭제하지 않음
- 트랜잭션 시작 후 실패하면 기존 회원과 회비 복구
- 성공 시 기존 회비와 회원 전체 삭제
- 성공 시 예상 회원·연락처 건수 적재
- 성공 시 모든 운영자 프로필을 정확히 한 번 연결
- 성공 시 회원번호 카운터를 올바르게 이동

UI 및 작업 흐름:

- 데스크톱·모바일 회원 목록에 영구 회원번호와 Group 표시
- 목록, 등록·수정 폼, 모바일 상세에서 탈퇴 사유 제거
- Group A, B, 미지정 필터 동작
- 수동 등록 시 영구 번호 자동 발급과 중복 규칙 적용
- 회비 CSV가 영구 회원번호로만 활동 회원을 찾음
- 알 수 없거나 중복된 회비 회원번호가 있으면 파일 전체 거부
- 비어 있는 회비 이력에서도 정산과 보고서 정상 동작

완료 전 전체 검증:

- 회원, 회비, 권한, 마이그레이션, 초기화 집중 테스트
- `npm run test`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- 관리자·일반 운영자 회원 화면, 등록·수정, Group 필터, 중복 경고,
  회비 CSV 브라우저 검증
- 익명·일반 운영자·관리자 세션으로 DB RLS 검증

## 해결된 결정 사항

- 영구 회원번호는 초기 CSV에서 가져오고 이후 자동 발급한다.
- CSV를 최종 기준으로 사용하며 기존 회비 이력은 의도적으로 삭제한다.
- 기존 운영자 프로필은 유지하고 정규화된 이름으로 다시 연결한다.
- 전체 연락처는 권한으로 제한하고 일반 운영자는 마스킹 값만 본다.
- 이름이 다른 회원 간 연락처 공유는 경고 후 허용한다.
- Group은 기준 테이블로 확장 가능하게 만들고 초기값 A·B를 제공한다.
- Group 관리 UI와 기존 데이터 백업은 이번 범위에서 제외한다.
