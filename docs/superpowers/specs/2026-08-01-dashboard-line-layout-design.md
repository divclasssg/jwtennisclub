# 대시보드 라인형 레이아웃 및 금액 가시성 설계

## 목적

재무 중심 대시보드의 정보 구조는 유지하면서 다른 관리 화면과 동일한 구분선 중심 표현으로 정리한다. 대시보드에서 중복되는 셸 제목 바를 제거하고, 활동 회원 집계에서 회장용 회원번호 `#0000`을 제외하며, 그래프의 정확한 금액을 포인터나 키보드 조작 없이 항상 확인할 수 있게 한다.

## 확정 범위

- `shell-title-bar`는 `/dashboard`에서만 숨기고 데스크톱과 모바일에서 빈 행 높이도 제거한다.
- 다른 앱 화면의 셸 제목 바와 페이지 제목 동작은 변경하지 않는다.
- 대시보드의 `활동 회원` 수에서만 `member_code = '#0000'`을 제외한다.
- 활동 예정, 휴회, 이번 달 신규·휴회·탈퇴 집계의 기존 의미는 유지한다.
- 활동 회원 값 주변에 `회장(#0000) 제외`를 항상 표시한다.
- 두 재무 그래프 아래에 월별 정확한 금액을 항상 보이는 표로 표시한다.
- 대시보드의 검은 잔액 면과 둥근 카드 외곽을 모두 제거하고 흰 배경과 구분선으로 통일한다.
- 링크와 버튼은 작업 컨트롤로서 기존 형태와 색상 위계를 유지한다.

## 접근 방식

### 대시보드 전용 셸 표시 신호

대시보드 콘텐츠가 안정적인 데이터 속성으로 셸 제목 바 숨김 의도를 표시한다. AppShell SCSS는 `:has()`로 해당 신호를 감지해 제목 바를 숨기고 작업 공간의 그리드 행을 다시 계산한다. 서버가 렌더링한 DOM만으로 결정되므로 경로 문자열을 AppShell 클라이언트 코드에 결합하거나 hydration 뒤 제목 바가 사라지는 깜빡임을 만들지 않는다.

대시보드 본문에는 별도의 시각적 페이지 제목을 추가하지 않는다. 문서 구조에는 화면 판독기용 대시보드 `h1`을 유지하고, 보이는 섹션 제목은 현재 정보 순서를 그대로 따른다.

### 활동 회원 집계

운영에 적용된 `202608010001_add_dashboard_page.sql`은 변경하지 않는다. 새 `202608010002_exclude_president_from_dashboard_activity.sql` 전진 마이그레이션에서 `public.get_dashboard_page()`를 교체한다.

`active_count`의 필터에 `members.member_code <> '#0000'`을 추가한다. 이 규칙은 역할명이나 회원 이름이 아닌 확정된 예약 회원번호를 사용한다. 함수의 기존 인증 검사, 고정 `search_path`, 잠금, 재무 계산, 반환 JSON 계약과 권한 회수·부여는 그대로 유지한다.

### 그래프 금액 상시 표시

현재 화면 판독기용으로만 제공되는 표를 실제 표시되는 간결한 수치 표로 전환한다.

- 월별 수납·지출: 월, 실제 회비 수납액, 운영 지출
- 장부 잔액 추이: 월, 장부 잔액, 확정 또는 변동 가능 상태
- 모든 값은 원 단위 천 단위 구분과 `원` 접미사를 유지한다.
- 월은 그래프와 동일한 오름차순으로 표시한다.
- 표는 데스크톱에서 간결한 행, 휴대폰에서도 가로 스크롤 없이 읽을 수 있는 행 구조를 사용한다.
- SVG의 제목·설명과 표의 접근 가능한 이름은 유지한다. 정확한 금액 확인이 hover에 의존하지 않으므로 터치와 키보드 환경에서 같은 정보를 제공한다.

### 라인형 시각 체계

대시보드의 회원 요약, 현재 장부 잔액, 이번 달 재무, 두 그래프, 최근 최종 마감, 빈 상태와 오류 상태에서 둥근 외곽선과 카드형 배경을 제거한다.

- 바깥 컨테이너는 흰 배경과 상·하단 hairline을 사용한다.
- 한 행의 형제 항목은 세로 hairline으로 구분한다.
- 현재 장부 잔액의 검은 배경은 제거하되 큰 금액 크기와 변동 가능 표시는 유지한다.
- 재무 지표와 최근 마감 지표는 기존 반응형 열 수와 내부 구분선을 유지한다.
- 그래프 두 개는 별도 카드처럼 보이지 않도록 같은 라인형 규칙을 사용한다.
- 인접 영역의 선이 겹쳐 두껍게 보이지 않도록 각 영역의 상·하단 선 책임을 한 번만 정의한다.

기존 전역 디자인 토큰과 breakpoint만 사용하며 새 하드코딩 시각 값은 추가하지 않는다.

## 데이터 및 오류 흐름

페이지는 기존처럼 `get_dashboard_page()`를 한 번 호출한다. 파서와 TypeScript 반환 타입은 바뀌지 않는다. 새 집계 규칙은 `active_count` 값만 바꾸므로 클라이언트 데이터 계약 변경이나 배포 순서 호환 처리가 필요하지 않다.

마이그레이션을 먼저 적용하고 앱을 배포한다. 구 앱은 같은 JSON 계약을 계속 사용할 수 있다. RPC 실패 시 기존 대시보드 오류 경계와 다시 시도 동작을 유지하며 오류 패널만 라인형 표현으로 바꾼다.

## 테스트 및 검증

- AppShell 회귀 테스트: 대시보드 숨김 신호가 있을 때 제목 바와 빈 그리드 행이 제거되고 다른 화면은 유지된다.
- 대시보드 라우트 테스트: 화면 판독기용 `h1`, 섹션 순서와 숨김 신호를 확인한다.
- 집계 마이그레이션 테스트: `active_count`에서만 `#0000`이 제외되고 기존 함수 보안·권한 계약이 유지된다.
- 대시보드 요약 테스트: 활동 회원 수와 `회장(#0000) 제외` 설명이 함께 표시된다.
- 그래프 테스트: 두 금액표가 시각적으로 숨겨지지 않고 모든 월의 정확한 금액과 상태를 제공한다.
- 스타일 회귀 테스트: 대시보드 컨테이너에 둥근 카드 외곽과 검은 잔액 배경이 없고 hairline 구분 규칙이 존재한다.
- 전체 Vitest, ESLint, TypeScript, production build와 `git diff --check`를 실행한다.
- 마이그레이션 적용 후 인증 운영자 화면을 데스크톱과 휴대폰에서 확인해 제목 바 제거, `#0000` 제외 수치, 금액표, 가로 넘침, 콘솔 오류를 검증한다.

## 제외 범위

- 다른 화면의 AppShell 제목 바 제거
- 활동 회원 외의 회원·회비·결산 집계 정의 변경
- 그래프 종류, 기간, 색상 또는 재무 데이터 계약 변경
- hover 전용 툴팁 추가
- 대시보드 링크와 결산 작업 흐름 재설계
