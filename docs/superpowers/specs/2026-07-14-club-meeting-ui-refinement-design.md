# 정모 관리 UI 개선 설계

## 배경

정모 참석·출석 관리 기능은 운영 DB 적용과 권한 검증까지 완료됐지만, 실제 화면에서는 조회보다 관리 입력이 더 크게 보인다. 데스크톱 목록은 장소 변경·취소·마감 입력이 항상 펼쳐져 두 회차만으로도 행이 과도하게 높고, 모바일은 월 요약과 임시 대상 추가가 첫 화면을 대부분 차지해 핵심 작업인 회원별 응답·출석 입력까지 도달하는 데 스크롤이 많이 필요하다.

이번 개선은 기존 정모 데이터 모델, 권한, 서버 작업과 URL 계약을 유지하면서 운영자가 다음 두 작업을 더 빠르고 안전하게 처리하도록 정보 구조를 다듬는다.

1. 월별 회차를 빠르게 훑고 원하는 명단을 연다.
2. 명단에서 여러 회원의 사전 응답과 실제 출석을 연속으로 입력한다.

## 목표

- 회차 목록의 기본 상태에서는 조회 정보와 `명단` 작업을 우선한다.
- 장소 변경, 취소·복구, 출석 마감·재개, 번개 생성은 필요할 때만 펼친다.
- 모바일 첫 화면에서 월 요약과 필터가 차지하는 높이를 줄여 첫 회차를 바로 확인할 수 있게 한다.
- 명단 모달에서 검색·상태 필터·회원 상태 입력을 임시 대상 추가보다 먼저 제공한다.
- 반복 저장 버튼을 줄이되 기존 낙관적 동시성, 오류 복구, 접근 가능한 저장 상태 알림은 유지한다.
- 기존 Apple 스타일 디자인 토큰, 공통 원자·분자·조직 컴포넌트와 반응형 셸을 재사용한다.

## 비목표

- 정모, 명단, 참석, 출석 데이터 모델 변경
- Supabase 마이그레이션 또는 RPC 계약 변경
- 일반 회원 직접 응답 기능
- 회원별 누적 통계 화면
- 독립 번개 생성이나 새로운 정모 생명주기 작업
- 정모 관리와 무관한 전역 내비게이션 또는 다른 관리 화면 재설계
- 별도 Figma 산출물 제작

## 설계 원칙

### 스캔 우선

목록의 닫힌 기본 상태에는 회차 식별, 일시, 장소, 상태, 인원 요약과 `명단`만 보여준다. 입력 필드와 위험 작업은 기본 정보와 시각적으로 분리한다.

### 점진적 공개

회차 관리와 임시 대상 추가는 사용자가 명시적으로 펼친 뒤에만 표시한다. 기능을 숨기는 것이 아니라, 작업 빈도와 위험도에 따라 노출 순서를 조정한다.

### 명확한 주 작업

목록의 주 작업은 `명단 보기`, 명단 모달의 주 작업은 회원 상태 입력이다. 장소 변경·취소·마감과 임시 대상 추가는 보조 작업으로 취급한다.

### 기존 계약 보존

`month`, `meeting`, 검증된 `returnTo` 파라미터와 직접 접근·새로고침·닫기 후 포커스 복원 계약은 변경하지 않는다. 권한에 따른 읽기 전용 상태와 DB 측 검증도 그대로 유지한다.

## 월별 화면 구조

위에서부터 다음 순서로 배치한다.

1. 월 요약
2. 월 조회 필터
3. 조회 월·회차 수·월 명단 상태
4. 회차 목록

데스크톱 요약은 기존 네 칸 구조를 유지하되 내부 여백과 높이를 줄인 밀도 높은 변형을 사용한다. 모바일 요약은 세로 네 줄 대신 `전체 / 예정 / 완료 / 취소` 2×2 그리드로 표시한다. 필터는 월 입력과 조회 버튼을 한 줄에 유지한다.

월 명단 상태는 목록 헤더의 보조 정보로 유지한다. `최초 배포 월 · 통계 제외`, `월 명단 확정 · 통계 포함`, `다음 달 명단 준비 중`처럼 운영 판단에 필요한 전체 문구를 보존하되, 모바일에서는 회차 수 아래 한 줄 설명으로 배치한다.

## 데스크톱 회차 목록

### 기본 행

기본 행은 다음 정보를 제공한다.

- 회차: 제목과 정기·번개 구분
- 일시: 날짜와 시작·종료 시각
- 장소: 값이 없으면 `장소 미정`
- 상태: 예정·완료·취소
- 사전 참석 요약
- 실제 출석 요약
- `명단 보기`
- `관리` 펼침 작업

날짜, 종류, 제목, 시간을 지나치게 분리하지 않고 관련 정보를 묶어 가로 공간을 확보한다. 상태와 회차 종류는 기존 `Badge` 톤을 재사용한다. 사전·출석 요약은 각 상태명을 생략하지 않되 줄바꿈과 간격을 통제해 행 높이를 안정적으로 유지한다.

### 명단 작업

명단이 확정된 회차는 `명단 보기`를 항상 사용할 수 있다. 해당 월 명단이 아직 준비 중이면 링크 대신 비활성 `명단 준비 전` 상태와 생성 조건 설명을 제공한다. 비활성 요소를 활성 링크처럼 보이게 하지 않는다.

### 회차 관리 펼침 영역

`관리`는 해당 회차에 허용된 장소 변경, 취소·복구, 출석 마감·재개, 번개 생성을 펼치는 토글이다. 닫힌 상태에서는 입력 필드와 위험 작업을 렌더링 영역에서 숨겨 기본 행 높이를 늘리지 않는다.

펼친 영역은 다음 순서로 구성한다.

1. 현재 상태와 작업 가능 조건 설명
2. 장소 설정·변경
3. 출석 마감·재개
4. 취소·복구
5. 조건부 번개 생성

취소와 마감처럼 데이터 상태를 크게 바꾸는 작업은 기존 확인 절차를 유지하고 일반 저장 작업과 색상·간격으로 구분한다. 권한이 없는 사용자는 토글 자체를 보지 않으며 읽기 정보와 명단만 확인한다. 회차 관리 권한과 출석 관리 권한이 나뉜 경우 허용된 작업만 표시한다.

한 번에 여러 회차를 펼칠 수 있으나, 펼침 상태는 URL이나 서버에 저장하지 않는다. 월 변경이나 새로고침 후에는 모두 닫힌 기본 상태로 돌아간다.

## 모바일 회차 목록

모바일 카드는 다음 우선순위를 따른다.

1. 제목, 종류·상태 배지, `명단 보기`
2. 날짜·시간·장소
3. 대상·사전 참석·출석 요약
4. 접힌 `회차 관리`

핵심 정보는 카드 상단에서 한눈에 읽을 수 있게 하고, 보조 작업은 카드 하단의 펼침 영역에 둔다. 데스크톱과 동일한 정렬·집계·권한 결과를 사용한다.

요약 정보는 문장 세 개를 그대로 세로 배치하지 않는다. 대상 인원은 짧은 보조 문구로, 사전 참석과 출석은 두 개의 압축된 요약 행으로 제공한다. 상태명과 숫자는 보존해 색상만으로 의미를 전달하지 않는다.

모바일 관리 영역을 펼치면 입력 필드는 카드 너비를 사용하고 작업 버튼은 연결된 필드 가까이에 배치한다. 위험 작업 사이에는 충분한 간격을 두어 장소 저장과 취소를 잘못 누르지 않게 한다.

## 명단 모달 공통 구조

명단 모달은 다음 고정 순서를 사용한다.

1. 회차 제목과 닫기
2. 일시·장소·상태 요약
3. 사전 참석·출석 체크 탭
4. 현재 탭의 압축 상태 요약
5. 회원 검색과 상태 필터
6. 회원 목록
7. 접힌 `임시 대상 추가`
8. 접힌 `변경 이력`

헤더, 탭, 검색·필터 도구 모음은 모달 스크롤 중에도 현재 작업 맥락을 잃지 않도록 고정 영역으로 취급한다. 회원 목록과 하단 보조 영역만 내부 스크롤한다.

### 상태 요약

현재의 세로 다섯 칸 요약은 한 줄 또는 줄바꿈 가능한 압축 칩 묶음으로 바꾼다. 사전 참석 탭은 `전체 / 미응답 / 참석 / 늦참 / 불참`, 출석 체크 탭은 `전체 / 미체크 / 출석 / 지각 / 결석`을 표시한다.

각 칩은 숫자와 상태명을 함께 제공한다. 상태 필터와 결합할 수 있지만, 필터로 동작한다면 선택 상태와 키보드 조작을 명확히 구현하고 별도 필터 컨트롤과 중복되지 않게 한다.

### 검색과 필터

검색은 현재 불러온 명단에서 다음 값을 대상으로 클라이언트에서 즉시 필터링한다.

- 회원 이름
- 회원번호

상태 필터는 현재 탭의 상태 집합과 `전체`를 제공한다. 검색어와 상태 필터는 함께 적용한다. 결과가 없으면 `조건에 맞는 회원이 없습니다`와 필터 초기화 작업을 제공한다.

검색과 필터는 서버 데이터, URL, 회차 집계 순서를 바꾸지 않는다. 탭을 바꾸면 검색어는 유지하고 상태 필터만 새 탭의 `전체`로 초기화한다. 모달을 닫으면 검색·필터 상태는 폐기한다.

### 회원 행과 저장

회원 행은 회원번호, 이름, 그룹, 상태 선택, 조건부 도착 시간과 저장 상태를 제공한다. 회원 이름을 반복하는 긴 접근 가능한 이름은 유지하되 화면 레이블은 짧게 정리한다.

사전 참석은 `미응답 / 참석 / 늦참 / 불참` 선택 즉시 해당 행을 저장한다. 실제 출석은 `미체크 / 출석 / 결석` 선택 즉시 저장한다. `지각`을 선택하면 도착 시간 필드를 먼저 표시하고, 유효한 시간이 입력된 뒤 저장한다. 불완전한 지각 값은 서버로 보내지 않는다.

저장 중에는 해당 회원 행의 중복 변경만 막고 다른 행은 계속 편집할 수 있다. 성공하면 행 가까이에 짧은 `저장됨` 상태를 표시하고, 실패하면 서버 확정값으로 복원한 뒤 원인을 해당 행에 연결해 알린다. 기존 RSVP·출석별 CAS 토큰과 충돌 처리 계약을 그대로 사용한다.

자동 저장 때문에 상태가 조용히 바뀌지 않도록 `saving / saved / error`를 `aria-live` 상태로 알린다. 빠르게 연속 입력해도 앞선 요청이 뒤선 선택을 덮어쓰지 않게 행 단위 요청 순서를 보장한다.

### 임시 대상 추가

`임시 대상 추가`는 기본적으로 접혀 있고 제목 옆에 현재 회차에서 추가된 임시 대상 수를 표시한다. 펼친 뒤에만 회원 검색, 후보 선택, 추가 작업을 제공한다.

준비 중인 월, 읽기 전용 권한, 취소·마감 상태 등 기존 제한은 유지한다. 추가된 임시 대상은 일반 회원 목록 안에서 `임시` 배지로 구분한다. 삭제 가능 조건을 만족하는 임시 대상에만 제거 작업을 제공한다.

### 변경 이력

변경 이력은 기본적으로 접힌 보조 영역으로 유지한다. 펼치면 기존과 동일하게 장소 변경, 취소·복구, 마감·재개, 번개 생성, 임시 대상 추가·제거 이력을 최신순으로 표시한다.

## 데스크톱 명단 모달

모달의 최대 너비는 기존 큰 모달 변형을 유지하되, 화면 대부분을 무조건 채우는 대신 회원 목록을 충분히 볼 수 있는 범위에서 기존 반응형 토큰으로 제한한다. 한 회원은 가능한 한 한 줄에 표시한다.

검색 입력과 상태 필터는 같은 도구 모음에 배치한다. 회원 목록 헤더와 각 행의 열 정렬을 맞춰 반복 입력 시 시선 이동을 줄인다. 임시 대상 추가와 변경 이력은 회원 목록 아래에 두어 첫 화면에서 일반 회원 행이 더 많이 보이게 한다.

## 모바일 명단 모달

휴대전화에서는 기존 모달을 전체 화면 작업면처럼 사용한다. 상단 제목·닫기, 회차 요약, 탭, 검색·필터는 고정하고 회원 목록이 남은 높이를 스크롤한다.

모바일 첫 화면에는 최소한 다음이 보여야 한다.

- 회차 제목과 닫기
- 현재 탭
- 검색 또는 상태 필터
- 첫 번째 회원 행의 이름과 상태 입력

상태 요약은 한 줄 가로 스크롤 또는 두 줄 이내의 압축 레이아웃으로 제한한다. 임시 대상 추가는 회원 목록 뒤의 접힌 영역으로 이동해 첫 회원 입력을 밀어내지 않는다.

회원 행은 이름·회원번호·그룹을 한 묶음으로 표시하고 상태 입력을 충분한 너비로 제공한다. 지각 도착 시간은 상태 입력 바로 아래에 나타난다. 모바일의 버튼과 폼 컨트롤은 프로젝트의 편안한 터치 높이 토큰을 사용하며, 적절한 토큰이 없으면 의미 있는 전역 토큰을 추가한 뒤 사용한다.

## 준비·읽기 전용·오류 상태

### 명단 준비 전

- 목록의 명단 작업을 비활성 상태로 표시한다.
- `다음 달 명단은 전월 마지막 7일에 준비됩니다`처럼 생성 조건을 설명한다.
- 사전 참석과 출석 숫자를 0으로 오해할 수 있게 표시하지 않는다.

### 취소 또는 마감

- 취소 회차는 두 탭 모두 읽기 전용임을 모달 상단에 알린다.
- 마감 회차는 출석 체크가 읽기 전용이며 재개 권한과 조건이 있을 때만 회차 관리에서 재개 작업을 제공한다.
- 비활성 입력만 보여주지 않고 비활성 이유를 텍스트로 제공한다.

### 로딩과 오류

- 현재 서버 렌더링과 모달 데이터 로딩 방식을 유지한다.
- 행 저장 오류는 전체 모달 오류로 승격하지 않는다.
- 모달 자체를 열 수 없는 오류는 기존 안전한 목록 오류 상태를 유지한다.
- 검색 결과 없음과 실제 명단 없음은 다른 문구로 구분한다.

## 접근성

- 펼침 토글은 `aria-expanded`와 제어 영역의 연결을 제공한다.
- 탭, 검색, 상태 필터, 회원 행의 키보드 순서가 화면 순서와 일치해야 한다.
- 상태와 회차 종류는 색상뿐 아니라 텍스트로 구분한다.
- 자동 저장 결과와 오류는 행 단위 `aria-live` 영역으로 알린다.
- 모달의 `Escape`, 배경 클릭, 닫기, 닫은 뒤 포커스 복원 계약을 유지한다.
- 고정 헤더가 키보드 포커스를 가리거나 회원 행으로 이동하는 것을 방해하지 않아야 한다.
- 모바일 터치 컨트롤은 최소 WCAG 2.2 대상 크기를 충족하고, 제품 기준으로는 더 편안한 공통 터치 높이를 사용한다.
- 흐린 보조 텍스트는 기존 전역 토큰 중 충분한 대비를 가진 값을 우선하고, 브라우저 검증에서 실제 대비와 포커스 표시를 확인한다.

## 스타일과 구현 경계

- 모든 스타일은 SCSS Module로 작성한다.
- 클래스 이름은 의미 있는 kebab-case를 사용하고 BEM이나 camelCase를 사용하지 않는다.
- 색상, 글자 크기·굵기·행간·자간, 간격, 테두리, 반경, 그림자, breakpoint는 `src/app/globals.scss`와 `src/app/_breakpoints.scss`의 기존 토큰을 먼저 사용한다.
- 필요한 값이 없으면 구체적 화면 숫자를 직접 쓰지 않고 의미 있는 전역 토큰을 추가한다.
- 기존 `ManagementPageTemplate`, `SummaryGrid`, `SummaryCard`, `FilterBar`, `DataPanel`, `DataTable`, `Badge`, `ModalDialog`를 우선 재사용한다.
- 공통 컴포넌트의 기존 화면을 바꾸는 전역 수정은 피하고, 필요한 경우 명시적인 밀도 변형을 추가해 정모 화면에서만 선택한다.
- 검색과 상태 필터, 관리 펼침, 자동 저장 상태는 필요한 최소 클라이언트 경계 안에 둔다. 서버 페이지 전체를 클라이언트 컴포넌트로 전환하지 않는다.

## 검증 기준

### 기능

- 데스크톱 목록의 모든 회차 관리 입력은 기본 상태에서 닫혀 있다.
- `명단 보기`와 관리 펼침 작업은 기존 권한 조합을 정확히 반영한다.
- 준비 중인 명단은 활성 명단 링크로 보이지 않는다.
- 검색은 이름과 회원번호에 적용되고 상태 필터와 조합된다.
- 사전 응답과 지각 외 실제 출석 상태는 선택 후 행 단위로 저장된다.
- 지각은 유효한 도착 시간 없이는 저장되지 않는다.
- 낙관적 동시성 충돌 시 서버 값 복원과 재시도 흐름이 유지된다.
- 임시 대상 추가와 변경 이력은 접힌 상태에서 시작하며 기존 제한과 이력을 보존한다.
- 월, meeting, returnTo와 모달 닫기·포커스 복원 계약이 유지된다.

### 반응형과 시각

- 1440×900에서 두 회차의 닫힌 기본 행이 관리 입력 때문에 비정상적으로 늘어나지 않는다.
- 375×812에서 월 요약과 필터 뒤 첫 회차 카드의 제목·상태·명단 작업이 첫 화면에 보인다.
- 375×812 명단 모달 첫 화면에 첫 회원의 상태 입력이 보인다.
- 데스크톱과 모바일 모두 문서 가로 넘침이 없다.
- 펼친 관리 영역과 지각 시간 입력이 주변 컨트롤을 겹치거나 잘라내지 않는다.
- 명단이 많아도 페이지 전체가 아니라 기존 셸과 모달 내부 스크롤 규칙을 지킨다.

### 접근성

- 키보드만으로 월 조회, 명단 열기·닫기, 탭 전환, 검색·필터, 회원 상태 저장, 관리 펼침과 허용된 생명주기 작업을 수행할 수 있다.
- 저장 상태, 검증 오류, 비활성 이유를 스크린리더가 확인할 수 있다.
- 포커스 표시와 텍스트 대비를 실제 렌더링에서 검증한다.

### 회귀

- 정모 관련 컴포넌트·페이지·행 mutation 테스트를 갱신한다.
- 전체 테스트, lint, TypeScript 검사와 프로덕션 빌드를 통과한다.
- 인증된 admin 브라우저에서 데스크톱·모바일 목록과 명단을 검증한다.
- 브라우저 검증 중 실제 운영 상태를 변경했다면 원상 복구하고 감사 이력 영향까지 기록한다.

## 결정 사항

- 별도 Figma 작업 없이 코드베이스와 현재 화면 감사 결과를 설계 근거로 사용한다.
- 데이터·서버 계약은 유지하고 UI 구조와 클라이언트 상호작용만 개선한다.
- 기본 방향은 `스캔 우선 + 점진적 공개`다.
- 목록의 유일한 상시 주 작업은 `명단 보기`다.
- 명단의 주 작업은 회원 검색·필터와 행 단위 상태 입력이다.
- 임시 대상 추가, 변경 이력, 회차 생명주기 관리는 접힌 보조 작업이다.
