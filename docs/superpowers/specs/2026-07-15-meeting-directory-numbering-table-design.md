# 정모 누적 회차와 디렉터리 테이블 개선 설계

## 목표

정모 관리 화면의 한 셀에 여러 정보가 뭉쳐 있는 문제를 해결하고, 2026년 7월 18일 정모를 클럽 운영의 첫 정식 회차로 정의한다. 정모 회차는 월마다 초기화하지 않고 전체 기간에 걸쳐 1, 2, 3 순으로 누적한다. 상태와 구분은 버튼처럼 보이는 칩 대신 글자색으로 구분한다.

## 확정된 제품 규칙

- 2026년 7월 4일에 생성된 기존 정기 정모는 삭제한다.
- 2026년 7월 18일 정기 정모가 1회차다.
- 2026년 8월 1일은 2회차, 8월 15일은 3회차이며 이후에도 날짜순으로 누적한다.
- 정기 정모 일정은 기존처럼 매월 첫째·셋째 토요일에 생성한다. 2026년 7월만 시작일 이전의 첫째 토요일을 제외한다.
- `regular_occurrence`는 첫째·셋째 토요일이라는 일정 위치를 계속 표현한다. 사용자에게 보이는 누적 회차는 별도 필드로 관리한다.
- 정기 정모 제목은 누적 회차를 반영한 `1차 정모`, `2차 정모` 형식을 사용한다.
- 번개 정모는 독립 회차 번호를 만들지 않고 연결된 정기 정모의 관계를 유지한다.
- 번개 행의 회차 셀에는 연결된 정기 정모 번호를 `1 대체`처럼 표시해 독립 회차가 아님을 명확히 한다.

## 데이터 설계

### 누적 회차

`club_meetings`에 정기 정모용 누적 회차 필드를 추가한다. 정기 정모에는 양의 회차가 필요하고 번개 정모에는 값이 없어야 한다. 정기 정모 회차에는 부분 고유 인덱스를 적용한다.

회차는 현재 데이터의 최대값에 의존하지 않고 2026년 7월 18일을 기준으로 결정론적으로 계산한다. 기준 월의 셋째 토요일은 1이며, 이후 각 월의 첫째·셋째 토요일은 월 차이에 따라 연속 번호를 얻는다. 이 방식은 정모 생성 함수가 반복 실행되거나 여러 월이 준비되는 경우에도 같은 날짜에 같은 회차를 부여한다.

### 기존 데이터 정리와 백필

새 마이그레이션은 하나의 트랜잭션에서 다음 순서로 동작한다.

1. 2026년 7월 4일 정기 정모에 종속된 출석 대상과 생명주기 이력을 삭제한다.
2. 해당 정모 자체를 삭제한다.
3. 2026년 7월 18일 이후의 기존 정기 정모를 날짜순으로 백필한다.
4. 기존 정기 정모 제목을 누적 회차 기반으로 갱신한다.
5. 제약과 고유 인덱스를 적용한다.
6. 정모 자동 생성 함수와 대체 번개 제목 생성 로직을 새 회차 모델에 맞춘다.

7월 4일 정모에 연결된 번개 정모가 존재하면 조용히 연쇄 삭제하지 않는다. 마이그레이션을 중단해 예상하지 못한 운영 데이터를 먼저 확인하게 한다. 일반 출석 대상과 생명주기 이력은 삭제 대상 정모의 종속 데이터이므로 함께 제거한다.

## 정모 디렉터리 UI

### 데스크톱 테이블

선택된 B안인 2단 그룹 헤더를 적용한다.

- 기본 컬럼: `회차 | 구분 | 날짜 | 시간 | 장소 | 상태`
- `사전 참석` 그룹: `참석 | 늦참 | 불참 | 미응답`
- `출석` 그룹: `출석 | 지각 | 결석 | 미확인`
- 작업 컬럼: `명단 | 관리`

날짜와 시간은 서로 다른 컬럼으로 분리한다. 시작·종료 시간은 하나의 시간 셀에서 범위로 유지한다. 사전 참석과 출석은 그룹 헤더 아래 각각 한 숫자만 표시해 빠르게 비교할 수 있게 한다. 명단 준비 전에는 각 그룹 영역을 의미가 분명한 단일 안내 상태로 표현하고 접근 가능한 테이블 구조를 유지한다.

테이블은 넓어지므로 기존 데이터 패널의 내부 스크롤 경계를 사용한다. 페이지 전체에 가로 스크롤을 만들지 않는다.

### 칩 제거와 색상

데스크톱 테이블과 모바일 카드에서 정기·번개·연결 관계·예정·완료·취소 칩을 제거한다. 동일한 텍스트를 일반 인라인 요소로 표시하고 기존 전역 디자인 토큰으로 색을 구분한다.

- 정기 및 예정: 강조색
- 번개 및 보조 관계: 중립색
- 완료: 성공색
- 취소: 오류색

색상만으로 의미를 전달하지 않도록 상태 텍스트 자체는 항상 유지한다. 버튼과 링크의 기존 시각 표현은 변경하지 않는다.

### 모바일

모바일은 현재 카드 구조를 유지한다. 칩 영역만 색상 텍스트 행으로 바꾸고, 날짜·시간·장소 및 참석·출석 요약은 현재처럼 읽기 쉬운 세로 구조를 유지한다. 데스크톱의 다중 숫자 컬럼을 모바일에 그대로 복제하지 않는다.

## 데이터 흐름

디렉터리 RPC는 정모 누적 회차와 번개가 연결된 정기 정모의 누적 회차를 함께 반환한다. 서버 스키마와 `MeetingDirectoryRow`는 이 값을 검증하고 camelCase로 변환한다. 데스크톱 테이블과 모바일 목록은 동일한 회차 값을 사용한다. 번개 정모는 연결된 정기 정모 회차를 관계 표시용으로만 사용하고 독립 누적 번호를 부여하지 않는다.

## 오류 및 안전 처리

- 삭제 대상 날짜와 정기 정모 종류를 모두 확인해 다른 행을 삭제하지 않는다.
- 예상하지 못한 연결 번개가 있으면 마이그레이션 전체를 롤백한다.
- 누적 회차의 중복과 정기 정모의 누락 값을 데이터베이스 제약으로 차단한다.
- 자동 생성 함수는 반복 호출 시 기존 행을 유지하며 회차를 다시 소비하거나 건너뛰지 않는다.
- 마이그레이션 적용은 코드 검증과 별개로 운영 DB 상태를 확인한 뒤 실행한다.

## 테스트와 검증

- 회차 계산: 2026-07-18이 1, 2026-08-01이 2, 2026-08-15가 3인지 검증한다.
- 월·연도 경계: 이후 월과 연도 전환에서도 연속 번호를 검증한다.
- 마이그레이션: 7월 4일 삭제, 종속 데이터 정리, 연결 번개 안전 중단, 백필, 제약, 반복 실행 계약을 검증한다.
- 디렉터리 변환: RPC의 누적 회차가 모델에 정확히 전달되는지 검증한다.
- 테이블: 2단 헤더, 날짜·시간 분리, 참석·출석 세부 숫자 컬럼을 검증한다.
- 표현: 데스크톱과 모바일에 상태·구분 Badge가 없고 텍스트와 의미 있는 클래스가 남는지 검증한다.
- 반응형: 데스크톱 테이블은 패널 내부에서 스크롤되고 모바일 문서에는 가로 넘침이 없는지 확인한다.
- 전체 테스트, lint, TypeScript 검사와 프로덕션 빌드를 실행한다.

## 범위 밖

- 명단 모달 내부의 RSVP·출석 입력 컨트롤은 변경하지 않는다.
- 정모 생성 주기인 매월 첫째·셋째 토요일은 변경하지 않는다.
- 요약 카드와 회차 관리 버튼의 표현은 변경하지 않는다.
- 운영 DB 마이그레이션 실행은 코드 구현 완료 후 별도 검증 단계에서 다룬다.
