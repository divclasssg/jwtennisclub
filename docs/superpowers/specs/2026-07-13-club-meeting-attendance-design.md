# 정모 참석 및 출석 관리 설계

## 목표

운영진이 월 2회 정기 모임의 사전 참석 응답과 당일 실제 출석을 한곳에서 관리한다. 정모 취소와 대체 번개 모임의 이력을 보존하고, 향후 회원별 출석률과 지각률을 다시 계산할 수 있는 원본 데이터를 남긴다.

## 제품 범위

이번 범위에 포함한다.

- 매월 첫째·셋째 토요일 18:00~22:00 정기 정모 자동 생성
- 현재 월부터 다음 2개월까지 정모 회차 준비
- 전월 마지막 7일 동안 다음 달 활동중 회원 명단 준비
- 매월 1일 월별 대상 명단 확정
- 사전 참석 상태 `미응답 / 참석 / 늦참 / 불참`
- 실제 출석 상태 `미체크 / 출석 / 지각 / 결석`
- 지각 회원의 실제 도착 시간
- 출석 마감과 재개
- 정모 취소와 취소 정모에 연결된 번개 생성
- 정기 정모 장소 설정과 변경
- 월중 가입 회원의 회차별 임시 대상 추가
- 정모 관리 화면의 회차별 인원 요약
- 기존 일정 달력에 정모·취소·번개 표시

이번 범위에서 제외한다.

- 일반 회원 로그인과 회원 직접 응답
- 카카오톡, 문자, 푸시 알림
- 회원별 누적 출석률·지각률 화면
- 출석 데이터 CSV 내보내기
- 번개를 정기 정모 출석률에 포함하는 기능
- 취소 정모와 연결되지 않은 독립 번개 생성

## 확정된 운영 규칙

- 정기 정모는 각 달의 첫 번째 토요일과 세 번째 토요일에 열린다.
- 기본 시간은 18:00~22:00이다.
- 정기 정모는 날짜나 시간 변경으로 번개가 되지 않는다. 기상 악화 등으로 정모가 취소되면 취소 기록을 유지하고 별도의 연결된 번개를 만든다.
- 모든 활성 운영진은 정모 생성 보조 작업, 취소·복구, 참석 입력, 출석 체크, 마감·재개를 처리할 수 있다.
- 회원 가입·휴회·탈퇴 변경은 다음 달 시작 전 전월 마지막 7일 동안 정리한다.
- 매월 1일 당시 활동중 회원을 그달 첫째·셋째 주 정모의 공통 대상자로 확정한다.
- 1일 이후 회원 상태 변경은 이미 확정된 현재 월 명단을 바꾸지 않고 다음 달 명단에 반영한다.
- 1일 이후 가입한 회원이 당월 정모에 참석하면 운영진이 해당 회차의 임시 대상으로 추가할 수 있다. 임시 대상의 응답과 출석은 보존하지만 해당 월 정기 출석률 분모에서는 제외한다.
- 사전 `늦참` 응답은 예상 도착 시간을 요구하지 않는다.
- 실제 `지각`은 실제 도착 시간을 요구한다.
- 사전 `늦참` 회원이 정시에 도착하면 실제 상태는 `출석`이다.
- 정기 정모 출석률은 `출석 + 지각`을 참석으로 계산하고 지각률을 별도로 계산한다.
- 취소된 정모는 정기 정모 통계에서 제외한다.
- 연결된 번개는 별도 참여 통계 대상으로 취급한다.
- 일반 회원 직접 응답은 이번 범위에 포함하지 않는다. 외부 채널에서 받은 응답은 운영진이 앱에 전사하며 앱의 회차별 상태를 최종 원본으로 사용한다.
- 정기 정모의 날짜와 시간은 자동 규칙으로 고정하고 장소만 운영진이 설정하거나 변경할 수 있다.
- 번개의 `period_month`와 기본 제목의 월은 실제 번개 날짜가 아니라 연결된 정기 정모의 월을 따른다.
- 기능을 월 1일 이후에 처음 배포한 월은 정확한 1일자 회원 상태를 복원할 근거가 없으므로 `bootstrap` 명단으로 표시하고 후속 누적 출석률·지각률 계산에서는 제외한다. 다음 달부터 자동 확정한 명단만 통계 적격으로 사용한다.
- 준비 중인 다음 달 명단은 회원 자격뿐 아니라 회원번호·이름·그룹 변경도 같은 트랜잭션에서 최신 스냅샷으로 동기화한다.

## 정보 구조와 경로

주 내비게이션에 `정모 관리`를 추가하고 `/meetings` 경로를 사용한다. 기존 `/schedule`은 일반 일정과 정모를 함께 보여주지만 정모 수정의 원본 화면은 `/meetings` 하나로 제한한다.

정모 관리 화면은 월별 운영 테이블을 중심으로 구성한다. URL의 `month=YYYY-MM` 검색 파라미터로 조회 월을 유지한다. 명단 모달을 열 때는 `meeting=<uuid>` 검색 파라미터를 함께 사용한다. 일정 달력에서 정모 항목을 누르면 실제 개최일로 달력에 표시하되 `/meetings?month=<period_month>&meeting=<uuid>&returnTo=<검증된 일정 URL>`로 이동해 해당 모달을 바로 연다.

직접 URL 접근과 새로고침에서도 같은 회차를 불러오며, 존재하지 않거나 권한이 없는 회차 ID는 명단을 노출하지 않고 안전한 오류 상태를 표시한다.

목록에서 연 모달을 닫을 때는 `meeting` 검색 파라미터만 제거하고 `month`는 유지한다. 일정에서 연 경우에는 같은 출처이며 pathname이 정확히 `/schedule`인 URL만 허용한다. 서버는 허용된 `view`, `month`, `date`, `selectedDate`만 정규화해 새 상대 URL로 조립하고 원문 `returnTo`를 그대로 사용하지 않는다. 외부 URL이나 허용되지 않은 내부 경로는 무시한다. 직접 접근이나 새로고침으로 연 모달은 `/meetings?month=YYYY-MM`을 종료 목적지로 사용한다. 닫기 버튼, 배경 클릭, `Escape`는 같은 종료 목적지를 사용하고 브라우저 뒤로가기는 브라우저 이력에 따라 동일한 출처로 돌아간다. 목록에서 연 모달은 닫힌 뒤 해당 `명단` 작업으로 포커스를 돌려준다.

## 데이터 모델

### `club_meetings`

정모와 번개 회차의 단일 원본이다.

- `id`: UUID 기본 키
- `meeting_kind`: `regular` 또는 `lightning`
- `period_month`: 회차를 표시할 월의 첫날
- `regular_occurrence`: 정기 정모는 `1` 또는 `3`, 번개는 `null`
- `meeting_date`: 실제 모임 날짜
- `start_time`, `end_time`: 정기 정모 기본값 18:00, 22:00
- `title`: 화면과 일정 달력에 표시할 제목
- `location`: 장소가 없으면 `null`이며 화면에는 `장소 미정`으로 표시
- `linked_regular_meeting_id`: 번개가 대체하는 취소 정모 ID
- `cancelled_at`, `cancelled_by`, `cancellation_reason`: 취소 이력
- `attendance_closed_at`, `attendance_closed_by`: 출석 마감 이력
- `created_by`, `updated_by`, `created_at`, `updated_at`: 감사 필드

정기 정모는 `period_month + regular_occurrence` 조합의 부분 고유 인덱스로 중복 생성을 막는다. 정기 정모의 날짜와 시간은 자동 계산 규칙을 따르며 운영진이 직접 다른 날짜나 시간으로 변경하지 않는다. 장소는 운영진이 설정하거나 변경할 수 있다. 날짜나 시간 변경이 필요하면 정모를 취소하고 연결된 번개를 생성한다.

장소는 앞뒤 공백을 정리한 뒤 최대 200자, 취소 사유는 최대 500자로 제한한다. 번개 제목은 서버가 정해진 기본 형식으로 생성하며 클라이언트가 임의 제목을 전달하지 않는다.

화면 상태는 중복 컬럼으로 저장하지 않고 다음 우선순위로 계산한다.

1. `cancelled_at`이 있으면 `취소`
2. 취소가 아니고 `attendance_closed_at`이 있으면 `완료`
3. 나머지는 `예정`

번개는 취소된 정기 정모에서만 생성한다. `linked_regular_meeting_id`는 생성 시점에 취소된 `regular` 회차를 가리켜야 하며, 같은 취소 정모에 연결되는 번개는 하나만 허용한다. 번개 생성 시 날짜·시간·장소를 운영진이 입력하고 `period_month`는 연결된 정기 정모의 월을 사용한다. 제목 기본값은 `<정기 정모 월>월 <회차> 정모 대체 번개`로 채운다.

### `meeting_month_rosters`

한 달의 공통 출석 대상자 확정 상태를 관리한다.

- `id`: UUID 기본 키
- `period_month`: 월의 첫날, 고유 값
- `status`: `preparing` 또는 `locked`
- `roster_origin`: `automatic` 또는 최초 배포 월의 `bootstrap`
- `statistics_eligible`: 후속 누적 통계의 분모 사용 여부
- `locked_at`, `locked_by`: 확정 이력
- `created_at`, `updated_at`: 감사 필드

전월 마지막 7일 동안 다음 달 행은 `preparing` 상태다. 새달이 시작되면 현재 월 행을 `locked`로 바꾸며 이후 같은 월 명단은 회원 상태 변경으로 수정하지 않는다.

월 1일 이후 처음 배포되어 현재 월의 과거 회원 상태를 재구성할 수 없으면 현재 활동중 회원으로 `bootstrap` 명단을 잠그고 `statistics_eligible = false`로 둔다. 이 회차도 운영과 회차별 집계에는 정상 사용하지만 후속 회원별 누적 통계에서는 제외한다. 다음 달부터 생성되는 `automatic` 명단은 통계 적격이다.

### `meeting_month_roster_members`

월별 대상 회원 스냅샷이다.

- `id`: UUID 기본 키
- `roster_id`, `member_id`: 복합 고유 키
- `member_code_snapshot`
- `member_name_snapshot`
- `group_code_snapshot`
- `created_at`

회원번호·이름·그룹을 스냅샷으로 저장해 이후 회원 정보가 바뀌어도 과거 회차 화면과 통계 기준을 유지한다.
`member_id` 외래 키는 삭제 제한을 사용한다. 출석 이력이 있는 회원은 물리 삭제하지 않고 기존 회원 상태 변경 흐름으로 휴회·탈퇴 처리한다.

### `meeting_attendance`

회차별 사전 참석과 실제 출석을 저장한다.

- `meeting_id`, `member_id`: 복합 고유 키
- `roster_member_id`: 월별 대상자는 `meeting_month_roster_members.id`를 가리키고 임시 대상자는 `null`
- `target_origin`: `monthly_roster` 또는 `ad_hoc`
- `member_code_snapshot`, `member_name_snapshot`, `group_code_snapshot`
- `rsvp_status`: `unanswered`, `attending`, `late`, `declined`
- `attendance_status`: `unchecked`, `present`, `late`, `absent`
- `arrival_time`: 실제 지각 도착 시간
- `attendance_origin`: 초기 `unchecked` 상태에서는 `null`, 직접 입력은 `manual`, 마감 자동 결석은 `close_default`
- `rsvp_updated_by`, `rsvp_updated_at`
- `attendance_updated_by`, `attendance_updated_at`

`monthly_roster` 행은 `roster_member_id`가 필수이고 `ad_hoc` 행은 `null`이어야 한다. `(roster_member_id, member_id)`는 월별 명단의 같은 회원을 가리키는 복합 외래 키로 보호해 다른 회원의 스냅샷을 연결할 수 없게 한다. `member_id` 삭제는 제한한다.
월별 대상 행이 가리키는 roster의 `period_month`는 회차의 `period_month`와 반드시 같아야 하며 이 교차 테이블 불변 조건도 DB 제약 경계에서 검증한다.

응답과 출석의 `updated_at`은 행 생성부터 각각 non-null인 독립 CAS 토큰이다. 상태 저장은 클라이언트가 마지막으로 확인한 토큰과 DB 값을 원자적으로 비교하고, 성공할 때마다 해당 영역의 토큰을 반드시 더 큰 DB 생성 시각으로 바꾼다.

정기 정모의 출석 행은 확정된 해당 월 명단에서 `monthly_roster` 대상으로 생성한다. 같은 달 첫째·셋째 주 정모는 동일한 월별 대상자를 사용하지만 참석 상태는 회차별로 독립적이다. 월중 가입 회원은 운영진이 특정 회차에 `ad_hoc` 대상으로 추가하며 추가 시점의 회원번호·이름·그룹을 스냅샷으로 저장한다. `ad_hoc` 대상은 해당 회차의 응답·출석과 회차 인원 집계에는 포함하지만 정기 출석률과 지각률 분모에서는 제외한다.

잘못 추가한 `ad_hoc` 대상은 사전 응답이 `unanswered`, 실제 출석이 `unchecked`인 동안에만 제거할 수 있다. 한번이라도 응답이나 출석이 기록된 대상은 삭제할 수 없으며 원본 상태를 보존한다. 제거 작업도 수행 운영진과 시각을 생명주기 이력에 남긴다.

번개는 연결된 취소 정모의 월별 대상자와 이미 추가된 임시 대상자를 복제하고 모든 사전·실제 상태를 초기값으로 시작한다. 번개는 종류 자체로 정기 출석률과 지각률 집계에서 제외한다.

`arrival_time`은 실제 상태가 `late`일 때만 존재하며 정모 시작 시각보다 늦고 종료 시각 이내여야 한다. `present`, `absent`, `unchecked`로 바꾸면 기존 도착 시간을 제거한다.

### `meeting_lifecycle_events`

취소·복구·마감·재개·장소 변경·번개 생성의 감사 이력을 추가 전용으로 저장한다.

- `id`: UUID 기본 키
- `meeting_id`: 대상 회차
- `event_type`: `cancelled`, `restored`, `attendance_closed`, `attendance_reopened`, `location_updated`, `lightning_created`, `ad_hoc_added`, `ad_hoc_removed`
- `actor_profile_id`, `occurred_at`
- `reason`: 취소처럼 사유가 필요한 사건 외에는 `null`
- `details`: 변경 전후 값이나 연결 회차 ID처럼 사건별 보조 정보

현재 상태 판정을 위한 `cancelled_at`·`attendance_closed_at` 필드는 복구나 재개 시 제거할 수 있지만, 생명주기 사건은 수정·삭제하지 않는다. 따라서 취소 후 복구와 마감 후 재개가 반복되어도 각 수행 운영진, 시각, 사유를 다시 확인할 수 있다. `lightning_created`의 `meeting_id`는 생성된 번개를 가리키고 `details`에 원 정모 ID를 남긴다.

## 자동 생성과 월별 명단 확정

`/meetings`를 열면 서버는 순수 조회 RPC와 분리된 명시적 prepare/ensure command RPC로 선택 월 조회 전에 현재 월부터 다음 2개월까지 정기 정모 회차를 보장한다. 이 명령은 캐시 가능한 읽기로 취급하지 않으며 `meetings.view`를 가진 활성 운영자가 실행할 수 있다. 각 달의 첫 번째·세 번째 토요일을 `Asia/Seoul` 기준으로 계산하고 고유 제약이 있는 upsert를 사용해 동시에 여러 운영진이 열어도 중복을 만들지 않는다.

마이그레이션 자체가 현재 월 명단을 반드시 한 번 시드한다. 적용일이 1일 이후면 그 행만 `bootstrap`으로 만들고 전체 수명 동안 `bootstrap`은 최대 한 건만 허용한다. 이후 오랫동안 화면이나 회원 작업이 없었더라도 누락 월은 `automatic`으로 생성한다.

월별 명단은 다음 절차를 따른다.

1. 전월 마지막 7일에 다음 달 `preparing` 명단이 없으면 현재 활동중 회원으로 생성한다.
2. 이 기간의 회원 생성·상태·회원번호·이름·그룹 변경과 다음 달 준비 명단 동기화는 하나의 DB 트랜잭션으로 처리한다.
3. 매월 1일 이후 첫 정모 조회는 현재 활동중 회원 상태를 사용해 누락된 현재 월 명단을 만든 뒤 즉시 잠근다.
4. 매월 1일 이후 첫 작업이 회원 생성·상태·회원번호·이름·그룹 변경이면 회원 변경을 적용하기 전에 현재 월 명단을 먼저 생성·잠근다.
5. 잠긴 현재 월 명단은 이후 회원 변경으로 수정하지 않는다.

최초 기능 배포가 월 1일 이후라면 3번에서 만든 현재 월 명단은 `bootstrap`이자 통계 제외 상태로 잠근다. 이후 월에는 같은 예외를 반복하지 않는다.

준비 중인 미래 월의 정모를 미리 취소해 대체 번개를 만든 경우, 번개 생성 시점에는 확정 대상이 없을 수 있다. 월 명단을 잠그는 트랜잭션이 같은 월의 정기 정모와 이미 생성된 대체 번개 모두에 확정 대상 행을 멱등 생성해 빈 번개 명단이 남지 않게 한다.

이 방식은 별도 예약 작업 없이도 월 경계를 지킨다. 앱을 거치지 않은 직접 DB 수정은 이 자동 동기화 계약의 대상이 아니다.

회차 준비, 현재 명단 잠금, 다음 명단 동기화는 월별 transaction advisory lock을 월 오름차순으로 획득하고 같은 테이블 잠금 순서를 따른다. authenticated 역할의 회원 직접 쓰기는 회수해 앱 사용자가 동기화 RPC를 우회하지 못하게 한다. service role이나 운영자가 SQL 콘솔에서 수행하는 직접 DB 수정은 계속 자동 동기화 계약 밖이다.

## 정모 관리 화면

### 월별 회차 목록

기존 인증 화면의 고정 셸과 내부 스크롤 규칙을 유지한다. 본문에는 기존 `DataPanel`, `FilterBar`, `SummaryGrid`, `DataTable` 패턴을 재사용한다.

- 월 선택과 조회 작업
- 전체 회차, 예정, 완료, 취소 수 요약
- 회차, 종류, 일시, 장소, 상태
- 사전 참석, 늦참, 불참, 미응답 수
- 실제 출석, 지각, 결석, 미체크 수
- `명단`, `취소/취소 복구`, `출석 마감/재개`, `번개 만들기` 작업
- 정기 정모의 `장소 설정/변경` 작업

`번개 만들기`는 취소된 정기 정모 행에만 표시하며, 과거에 취소된 번개까지 포함해 연결 번개가 하나라도 존재하면 다시 제공하지 않는다. 자동 생성되는 정기 정모를 위한 수동 등록 버튼과 독립 번개 등록 버튼은 제공하지 않는다.

아직 월별 명단이 확정되지 않은 미래 회차는 참석 수를 `0`으로 표시하지 않고 `명단 준비 전`으로 표시한다. 명단 확정 이후에만 상태별 인원 수를 표시한다.

데스크톱은 밀도 높은 표를 사용하고, 모바일은 기존 회원·회비 화면처럼 회차별 카드 목록으로 전환한다. 데스크톱과 모바일은 같은 정렬·집계 결과를 사용한다.

### 명단 모달

`명단`은 기존 `ModalDialog`를 확장한 큰 모달로 연다. 모달은 회차 제목, 일시, 장소, 상태를 표시하고 `사전 참석`과 `출석 체크` 두 탭을 제공한다. 회차 정보만을 위한 세 번째 탭은 만들지 않는다.

사전 참석 탭은 상태별 인원 요약과 회원번호·이름·그룹·상태 선택을 보여준다. 각 회원의 `미응답 / 참석 / 늦참 / 불참` 변경은 그 회원의 행만 저장한다. 미응답은 별도 선택 또는 선택 해제로 복원할 수 있다.

출석 체크 탭은 `미체크 / 출석 / 지각 / 결석`을 제공한다. 지각을 선택하면 같은 행에서 도착 시간을 입력한 뒤 저장한다. 모달 본문만 내부 스크롤하며 헤더와 탭은 유지한다.

명단에 없는 활동중 회원은 월 명단이 `locked`로 확정된 뒤 `임시 대상 추가`로 현재 회차에만 추가할 수 있다. 준비 중인 월에는 대상 자격이 아직 변할 수 있으므로 임시 대상을 추가하거나 후보로 노출하지 않는다. 이미 월별 대상이거나 같은 회차에 추가된 회원은 중복 추가할 수 없다.
아직 응답이나 실제 출석을 기록하지 않은 임시 대상은 제거할 수 있다. 기록이 시작된 대상은 제거 작업을 제공하지 않고 서버에서도 거부한다.

행 저장 상태는 `idle / saving / saved / error`로 구분한다. 저장 중에는 해당 행의 중복 입력만 막고 다른 행은 계속 처리할 수 있다. 성공과 실패는 접근 가능한 상태 메시지로 알리며, 실패 시 서버의 확정값으로 복원하고 해당 행에서 재시도할 수 있게 한다. 지각 시간 검증 오류는 해당 회원의 시간 입력과 연결해 표시한다.

실제 출석 입력은 회차 시작 시각부터 허용하고 출석 마감은 종료 시각 이후에만 허용한다. 사전 참석 입력은 회차가 취소되거나 출석 마감되기 전까지 허용한다.

취소된 회차는 명단을 읽기 전용으로 표시한다. 마감된 회차는 출석 체크를 읽기 전용으로 표시하고 `마감 재개` 후에만 수정할 수 있다. 사전 응답은 마감 이후에도 이력 조회가 가능하지만 수정할 수 없다.

회차 요약 영역에는 별도 탭을 추가하지 않고 접을 수 있는 `변경 이력` 영역을 둔다. 장소 변경, 취소·복구, 마감·재개, 번개 생성, 임시 대상 추가·제거 사건의 운영진·시각·사유 또는 변경 내용을 최신순으로 확인할 수 있다.

## 출석 마감과 재개

출석 마감은 확인 대화상자 후 DB 트랜잭션 하나로 처리한다.

1. 회차가 취소되지 않았고 아직 마감되지 않았는지 확인한다.
2. 실제 상태가 `unchecked`인 행을 `absent`로 바꾼다.
3. 자동 결석 행의 `attendance_origin`을 `close_default`로 기록한다.
4. 회차의 마감 시각과 운영진을 기록한다.

재개도 트랜잭션으로 처리한다. `close_default`로 생성된 결석만 `unchecked`로 되돌리고, 운영진이 직접 입력한 결석은 유지한다. 회차의 현재 마감 필드를 지운 뒤 출석 수정을 다시 허용하며 기존 마감과 새 재개 사건은 `meeting_lifecycle_events`에 모두 보존한다.

## 취소, 취소 복구, 번개

정모 취소는 사유를 필수로 받고 확인 후 처리한다. 취소된 회차는 사전 참석·출석 변경과 마감을 막으며 정기 정모 통계 분모에서 제외한다. 기존 응답과 출석 데이터는 삭제하지 않고 이력으로 보존한다.

취소 복구는 현재 취소 시각·운영진·사유를 제거하고 기존 응답과 출석 데이터를 다시 활성화한다. 과거 취소와 새 복구 사건은 `meeting_lifecycle_events`에 모두 보존한다. 취소되지 않은 연결 번개가 있으면 정모를 복구할 수 없으며, 먼저 연결된 번개를 취소해야 한다. 취소된 번개의 연결은 이력 보존을 위해 유지하고 그 상태에서는 정기 정모를 복구할 수 있다.

취소된 번개는 다시 복구하지 않는다. 연결된 정기 정모를 복구한 뒤 과거 번개가 다시 활성화되어 두 회차가 동시에 예정 상태가 되는 흐름을 허용하지 않는다. 번개 자체의 삭제도 제공하지 않는다.

회차 종류와 상태별 주요 작업은 다음으로 고정한다.

| 회차 | 상태 | 허용 작업 |
| --- | --- | --- |
| 정기 정모 | 예정 | 장소 변경, 취소, 참석·출석 입력, 조건 충족 시 마감 |
| 정기 정모 | 취소, 연결 번개 없음 | 복구 또는 번개 생성 |
| 정기 정모 | 취소, 활성 번개 있음 | 번개를 먼저 취소해야 복구 가능, 추가 번개 생성 불가 |
| 정기 정모 | 취소, 취소 번개 있음 | 복구 가능, 추가 번개 생성 불가 |
| 번개 | 예정 | 취소, 참석·출석 입력, 조건 충족 시 마감 |
| 번개 | 취소 | 읽기 전용, 복구·삭제 불가 |

연결 번개는 상태와 무관하게 원 정모당 평생 한 건만 허용한다.

이미 출석 마감된 회차를 취소하려면 먼저 마감을 재개해야 한다. 이 순서를 서버와 DB에서 함께 검증한다.

번개 생성 시 연결된 취소 정모의 월별 대상자를 복제하지만 응답과 출석 상태는 모두 초기화한다. 번개는 독립적으로 참석 입력, 출석 체크, 마감·재개할 수 있다. 정기 정모 출석률과 지각률 집계에서는 항상 제외한다.

후속 회원별 통계의 계산 계약은 미리 고정한다. `statistics_eligible = true`인 월 명단에 속한 완료·비취소 정기 정모만 분모에 포함하고, 출석률은 `(출석 + 지각) / 대상 회차 수`, 지각률은 `지각 / 대상 회차 수`로 계산한다. 따라서 출석률은 정시 출석과 지각을 모두 포함하고 지각률은 그중 지각 부분을 별도로 보여준다. `bootstrap` 명단과 `ad_hoc` 대상, 번개는 분모와 분자에서 제외한다.

## 일정 달력 통합

기존 `events`에는 정모를 복제하지 않는다. `/schedule` 서버 로더가 선택 기간의 `events`와 `club_meetings`를 각각 조회한 뒤 공통 달력 표시 모델로 합친다.

월간 보기는 표시 월의 시작일부터 마지막일까지, 주간 보기는 화면에 보이는 실제 7일 범위를 `meeting_date`로 조회한다. 월 경계 주간도 인접 월의 항목을 누락하지 않는다. 실제 날짜가 `period_month`와 다른 번개는 실제 개최일에 표시하되 정모 링크의 `month`에는 `period_month`를 사용한다.

- 정기 정모: `정모` 표식
- 취소 정모: `취소` 표식과 취소된 시각 처리
- 번개: `번개` 표식
- 장소가 없으면 `장소 미정`

기존 일반 일정의 수정·삭제 링크는 유지한다. 정모와 번개는 일정 편집 화면으로 연결하지 않고 정모 관리 명단 모달 URL로 연결한다. `events.view`와 `meetings.view`가 모두 있는 상태에서 두 조회 중 하나라도 실패하면 불완전한 달력을 정상 결과처럼 표시하지 않고 일정 로드 오류를 제공한다. `events.view`만 있으면 정모를 조회하지 않고 기존 일반 일정만 정상 표시한다.

## 권한과 보안

향후 역할별 권한 편집을 위해 권한을 분리한다.

- `meetings.view`
- `meetings.manage`
- `meetings.attendance.manage`

현재 `admin`과 `operator` 역할 모두 세 권한을 받는다. 조회, 회차 변경, 참석·출석 변경은 각각 대응 권한을 서버 작업과 Supabase RLS에서 확인한다. 일반 회원과 미인증 사용자는 정모·명단 데이터를 읽거나 변경할 수 없다.

권한 조합별 화면과 서버 동작은 다음과 같다.

| 권한 | 화면 | 허용 작업 |
| --- | --- | --- |
| `meetings.view` 없음 | 주 내비게이션에서 숨기고 직접 경로를 안전하게 차단 | 없음 |
| `meetings.view`만 있음 | 목록·명단·변경 이력 읽기 전용 | 없음 |
| `meetings.view` + `meetings.manage` | 출석 입력은 읽기 전용 | 장소 변경, 취소·복구, 번개 생성 |
| `meetings.view` + `meetings.attendance.manage` | 회차 관리 작업은 숨김 | 임시 대상 추가·제거, 사전 응답·실제 출석 입력 |
| 세 권한 모두 | 모든 관리 화면 활성 | 위 작업과 출석 마감·재개 |

버튼 노출은 사용성을 위한 보조 수단일 뿐이며 각 DB 함수가 항상 실제 권한을 다시 판정한다.

모든 변경 RPC는 `meetings.view`와 작업별 특수 권한을 함께 요구한다. 출석 행을 일괄 변경하는 마감·재개는 `meetings.manage`와 `meetings.attendance.manage`를 모두 요구한다.

감사 필드는 `auth.uid()`와 일치해야 한다. 월별 명단 확정, 회차 취소·복구, 번개 생성, 참석 변경, 출석 마감·재개는 수행 운영진과 시각을 남긴다. 클라이언트는 actor, 사건 시각, 임의 details를 전달하지 않으며 RPC가 잠근 DB 행의 변경 전후 값과 DB 시각으로 사건을 만든다.

정모 관련 테이블의 직접 `insert`, `update`, `delete`는 `authenticated` 역할에 허용하지 않는다. 자동 생성, 명단 준비·확정, 장소 변경, 임시 대상 추가, 취소·복구, 번개 생성, 응답·출석 변경, 마감·재개는 작업별 PostgreSQL 함수로만 처리한다. 각 함수는 대응 권한과 활성 프로필을 `auth.uid()`로 다시 확인하고, 고정 `search_path`, `public`·`anon` 실행 권한 회수, 필요한 `authenticated` 실행 권한만 부여하는 기존 보안 경계를 따른다.

내부 헬퍼 함수는 `PUBLIC`, `anon`, `authenticated`의 실행 권한을 모두 회수하고 외부 작업 래퍼만 정확한 함수 시그니처 단위로 `authenticated` 실행을 허용한다. 각 작업은 대상 회차를 먼저 잠그고 회차·회원·월 명단·연결 정모 관계를 DB에서 유도해 검증하며, 클라이언트가 전달한 다른 회차나 다른 월 ID를 조합할 수 없게 한다.

`/schedule`은 기존 `events.view` 권한을 진입 기준으로 유지한다. `meetings.view`가 없는 사용자는 일반 일정만 정상 조회하고 정모 소스는 조회하지 않는다. `meetings.view`가 있는 상태에서 정모 조회가 실패한 경우에만 전체 일정 로드 오류로 처리한다.

## 오류 처리와 데이터 무결성

- 잘못된 월, 날짜, 시간, 상태 값은 서버에서 거부한다.
- 종료 시각은 시작 시각보다 늦어야 한다.
- 지각 도착 시간은 시작 시각보다 늦고 종료 시각 이내여야 한다.
- 실제 출석 입력은 시작 전, 출석 마감은 종료 전에 거부한다.
- 취소 회차의 변경, 마감 회차의 출석 변경, 중복 번개 생성은 DB에서도 거부한다.
- 자동 생성과 명단 생성은 고유 제약과 upsert로 멱등성을 보장한다.
- 회원별 상태 변경은 해당 출석 행만 갱신해 다른 회원 입력을 덮어쓰지 않는다.
- 같은 상태 필드를 두 운영진이 동시에 변경하면 요청이 가진 마지막 확인 시각과 DB의 갱신 시각을 비교해 오래된 요청을 거부하고 최신 상태를 다시 불러오게 한다.
- 취소·복구·마감·재개·번개 생성은 전체가 성공할 때만 반영되는 트랜잭션으로 처리한다.
- 저장 실패 시 낙관적으로 성공 상태를 유지하지 않고 모달 안에 작업 가능한 한국어 오류를 표시한다.
- 모든 날짜·시간 계산과 화면 표시는 `Asia/Seoul`을 기준으로 한다.
- DB의 현재 일시 판정도 세션 기본 시간대에 의존하지 않고 `Asia/Seoul`로 명시 변환한다.

## 디자인과 반응형 규칙

새로운 시각 언어를 만들지 않고 현재 인증 화면의 Figma 기반 스타일을 따른다.

- 앱 셸의 사용자 바와 제목 바 유지
- 본문 `PageHeader`를 다시 추가하지 않음
- 기존 흰색 면, 얇은 구분선, 파란 액션 색상 사용
- 기존 공용 atoms, molecules, organisms, templates 우선 재사용
- 전체 문서가 아닌 표·목록·모달 본문만 내부 스크롤
- SCSS와 기존 `src/app/globals.scss` 토큰 사용
- 새 값이 필요하면 의미 있는 전역 토큰을 먼저 추가
- CSS Module 클래스는 의미 있는 kebab-case 사용
- BEM, camelCase, 임의 전역 접두사 사용 금지
- 기존 `_breakpoints.scss` 변수를 사용해 데스크톱 표를 모바일 카드·목록으로 전환
- 모달이 열리면 제목 또는 첫 유효 작업으로 포커스를 이동하고 포커스를 모달 안에 유지하며, 닫힌 뒤 호출 요소로 복귀
- 탭은 `tablist`, `tab`, `tabpanel` 의미와 좌우 방향키·`Home`·`End` 동작 제공
- 반복되는 상태 선택과 도착 시간 입력의 접근 가능한 이름에 회원 이름 포함
- 저장·오류 상태를 `aria-live`로 전달하고 모바일 작업 컨트롤은 기존 터치 대상 토큰 이상으로 유지

## 완료 기준

- 모든 활성 운영진이 한 화면에서 월별 정모 상태와 회차별 인원 집계를 확인할 수 있다.
- 사전 응답과 실제 출석이 독립적으로 저장되며 지각 도착 시간이 보존된다.
- 월중 가입 회원의 실제 참석을 회차별로 보존하면서 정기 출석률 분모는 잠긴 월별 명단으로 유지한다.
- 전월 마지막 주 회원 변경이 다음 달 명단에 반영되고, 확정된 월의 과거 분모는 바뀌지 않는다.
- 출석 마감·재개가 수동 결석과 자동 결석을 구분해 되돌릴 수 있다.
- 취소 정모와 번개 이력이 보존되고 정기 정모 통계에 섞이지 않는다.
- 취소·복구·마감·재개가 반복되어도 각 사건의 운영진·시각·사유가 추가 전용 이력으로 보존된다.
- 기존 일정 달력에서 일반 일정과 정모를 중복 데이터 없이 함께 확인할 수 있다.
- 데스크톱과 모바일이 기존 디자인 체계와 내부 스크롤 규칙을 유지한다.
- 집중 테스트와 전체 회귀 검증, lint, typecheck, 프로덕션 빌드가 통과한다.
